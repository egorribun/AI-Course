1. Четыре способа получить производную

Представим, что нужна производная функции $f(x) = x^3 + 2x^2 + 1$. Есть четыре пути:

1.1 Аналитически (руками на доске)

По правилам дифференцирования: $f'(x) = 3x^2 + 4x$. Потом подставляем число.

Плюсы: точно, понимаем структуру.

Минусы: для сложных функций непрактично, для нейросети с млн параметров невозможно.

1.2 Символьно (SymPy, Mathematica, Maple)

Даём формулу программе, она применяет правила дифференцирования к выражению, выводит формулу производной. Потом вычисляем.

Плюсы: точно, можно символьно упростить.

Минусы: выражение может разрастись экспоненциально. Пример: производная от $(x^2 + x^3)^{100}$ — гигантская. На нейросетях время вычисления становится неприемлемо.

1.3 Численно (конечные разности)

$$ f'(x) \approx \frac{f(x + \varepsilon) - f(x - \varepsilon)}{2\varepsilon} $$ Центральная разность, ошибка $O(\varepsilon^2)$

Плюсы: работает для любой функции, даже если код чёрный ящик.

Минусы: два типа ошибок одновременно. (1) Ошибка отсечения ($\varepsilon$ не нулевая). (2) Ошибка округления (float32 точность $\sim 10^{-7}$). Оптимальный $\varepsilon \sim 10^{-4}$ (компромисс). Для каждого параметра нужен отдельный вызов функции — для $P$ параметров требуется $2P$ вызовов.

На практике: используют для проверки (gradient checking), а не для реального обучения.

1.4 Автоматически (Autodiff)

Разложить вычисление на элементарные операции (сложение, умножение, $\sin$, $\exp$), к каждой применить цепное правило, и распространить производные. Всё в конкретных числах, не в символьных переменных.

Плюсы: точность машинная (только машинная ошибка округления), один проход считает все градиенты сразу, эффективно.

Минусы: (почти нет!) нужна специальная структура — знать элементарные операции и их производные.

2. Автодифференцирование — не символьное, не численное

Здесь ключевая идея. Мы не выводим символьную формулу и не делаем численную аппроксимацию. Вместо этого:

💡 Суть автодифференцирования

Любое вычисление — это композиция элементарных операций ($+, \times, \sin, \exp$…). У каждой есть известная производная. Применяем цепное правило к конкретным числам, не к символам. Результат — производная в этой точке, с точностью машины.

Пример: $f(x_1, x_2) = x_1 \cdot x_2 + \sin(x_1)$. При $x_1 = 1, x_2 = 2$: вычисляем $f = 2 + \sin(1) \approx 2.841$, и одновременно $\frac{\partial f}{\partial x_1} \approx 2.541$, $\frac{\partial f}{\partial x_2} = 1$ — всё в числах.

Два режима распространения производных:

  • Forward mode: идём от входов к выходам, накапливая производные входов по параметрам (дуальные числа).
  • Reverse mode: сначала forward вычисляем и сохраняем граф, потом идём назад, распространяя производные выходов.

В нейросетях используется reverse mode — это и есть обратное распространение ошибки (backprop).

3. Вычислительный граф

Вычисление можно представить как ориентированный граф, где узлы — переменные, рёбра — операции.

Пример: $f(x_1, x_2) = (x_1 \cdot x_2 + \sin(x_1))^2$. При $x_1 = 2, x_2 = 3$.

4. Forward mode (прямой режим)

Распространяем производные вперёд вместе со значениями.

4.1 Дуальные числа

Представляем число в виде пары: $(x, \dot{x})$, где $x$ — значение, $\dot{x}$ — производная по интересующему нас параметру.

Правила арифметики для дуальных чисел:

$$ (x, \dot{x}) + (y, \dot{y}) = (x + y, \dot{x} + \dot{y}) $$ $$ (x, \dot{x}) \times (y, \dot{y}) = (xy, x\dot{y} + y\dot{x}) $$ $$ \sin(x, \dot{x}) = (\sin x, \cos x \cdot \dot{x}) $$

4.2 Числовой пример

Вычисли $f(x) = x^2 + \sin(x)$ и $f'(x)$ при $x = 1$. Forward mode:

  • Инициализируем: $(x, \dot{x}) = (1, 1)$ — значение 1, производная по входу = 1.
  • Вычисляем $x^2$: $(1, 1) \times (1, 1) = (1, 1 \cdot 1 + 1 \cdot 1) = (1, 2)$.
  • Вычисляем $\sin(x)$: $\sin(1, 1) = (\sin 1, \cos 1 \cdot 1) = (0.841, 0.540)$.
  • Складываем: $(1, 2) + (0.841, 0.540) = (1.841, 2.540)$.
  • Результат: $f(1) = 1.841$, $f'(1) = 2.540$ ✓

4.3 Стоимость и когда применяется

На каждый вход нужен отдельный forward pass. Если входов $n$, выходов $m$, операций $O$, то стоимость = $O(n \cdot O)$.

Когда forward mode выгоден? Когда входов мало, выходов много. Пример: физическая система с 2 параметрами и 1000 датчиков.

5. Reverse mode (обратный режим) = Backprop

Это правильный режим для нейросетей.

5.1 Два прохода: forward и backward

Forward pass: вычисляем значение функции обычно, но сохраняем граф вычислений (какие операции в каком порядке, какие значения были).

Backward pass: идём по графу в обратном порядке, считаем производные по цепному правилу. Стоимость одного backward pass $\approx$ одного forward pass.

5.2 Ключевая величина: адъюнкты

Определим адъюнкт (adjoint) — это $\frac{\partial \text{loss}}{\partial z}$ для промежуточного значения $z$.

$$ \bar{z} = \frac{\partial L}{\partial z} $$ Верхняя черта — обозначение для адъюнкта. Это «сколько ошибка зависит от этого значения».

Цепное правило в обратном режиме:

$$ \bar{x} = \bar{z} \cdot \frac{\partial z}{\partial x} $$

Если $z$ зависит от нескольких переменных, адъюнкты суммируются:

$$ \bar{x} = \sum_j \bar{z_j} \cdot \frac{\partial z_j}{\partial x} $$

5.3 Числовой пример: обратный проход

Функция $L = (x + y)^2$ с $x = 2, y = 3$. Найти $\frac{\partial L}{\partial x}$ и $\frac{\partial L}{\partial y}$.

  • Forward: $z = x + y = 5$, $L = z^2 = 25$.
  • Backward: $\bar{L} = 1$ (по определению). $\bar{z} = \frac{\partial L}{\partial z} = 2z = 10$.
  • $\bar{x} = \bar{z} \cdot \frac{\partial z}{\partial x} = 10 \cdot 1 = 10$. $\bar{y} = \bar{z} \cdot \frac{\partial z}{\partial y} = 10 \cdot 1 = 10$.
  • Проверка: $\frac{\partial L}{\partial x} = 2(x+y) = 10$ ✓, $\frac{\partial L}{\partial y} = 2(x+y) = 10$ ✓.

5.4 Reverse mode более выгоден для нейросетей

В нейросети: входов $n$ (признаки), параметров $P$ (веса), выходов $m$ (предсказания), 1 скаляр loss.

  • Forward mode: $n$ проходов для получения $\frac{\partial L}{\partial x_i}$. Но нам нужны $\frac{\partial L}{\partial w_{ij}}$ — параметры! Нужно $P$ проходов. Стоимость = $O(P \cdot T_{\text{forward}})$.
  • Reverse mode: один backward pass считает все $\frac{\partial L}{\partial w_{ij}}$ сразу. Стоимость = $O(T_{\text{backward}}) \approx O(T_{\text{forward}})$.

Вывод: reverse mode выигрывает в $\frac{P}{m} \approx \frac{P}{1} \sim 10^6$ раз для больших сетей.

6. Когда какой режим применять

РежимСтоимостьВыгоден когдаПримеры
ForwardO(n · T) где n = число входовВходов мало, выходов многоКалибровка 2 параметров под 1000 датчиков
ReverseO(m · T) где m = число выходовВходов много, выходов малоНейросети (входов 1000, выход 1 (loss))
Специальный случай: если входов и выходов поровну, оба режима примерно одинаковы по стоимости. Но reverse часто быстрее на практике (лучше cache).

Главный тезис для экзамена: Backprop = reverse-mode autodiff применённый к нейросети. Это не отдельный алгоритм, а частный случай общей техники автоматического дифференцирования.

7. Автодифф в PyTorch

7.1 Базовый пример

import torch

# Создаём тензоры с requires_grad=True — они отслеживают вычисления
x = torch.tensor([2.0, 3.0], requires_grad=True)
y = torch.tensor([1.0], requires_grad=True)

# Вычисляем функцию: L = (x[0] * x[1] + sin(x[0]))^2 - y
z = x[0] * x[1] + torch.sin(x[0])
L = (z ** 2) - y

# Обратное распространение: считаем ∂L/∂x и ∂L/∂y
L.backward()

# Градиенты теперь в .grad
print("∂L/∂x:", x.grad)  # tensor([ 126.87,  82.92])
print("∂L/∂y:", y.grad)  # tensor([-2.])

7.2 Ключевые концепции

requires_grad: указывает PyTorch строить граф вычислений для этого тензора. Листовые тензоры (tensor, не от операций) с requires_grad=True — это параметры.

Динамический граф: PyTorch строит граф во время forward pass. Это позволяет использовать условные операторы и циклы в коде — граф адаптируется.

Накопление градиентов: если вызвать .backward() дважды, градиенты складываются! Поэтому нужно opt.zero_grad() перед каждым backward.

7.3 torch.autograd.grad для частных производных

Чтобы получить производную конкретной переменной без обнуления других:

import torch

x = torch.tensor([2.0], requires_grad=True)
y = x**3

# Получить ∂y/∂x без .backward() (не затирает граф)
grad_y_x = torch.autograd.grad(y, x, create_graph=True)[0]
print(grad_y_x)  # tensor(12., grad_fn=...)

# Так можно считать вторые производные
grad2_y_x2 = torch.autograd.grad(grad_y_x, x)[0]
print(grad2_y_x2)  # tensor(12.) — вторая производная 3x^2 — это 6x = 12 при x=2

7.4 no_grad context — отключить tracking

with torch.no_grad():
    # Внутри не строится граф, быстро, экономит память
    predictions = model(x)
    loss_test = loss_fn(predictions, y)

Используется при инференсе и валидации — не нужны градиенты.

7.5 Детали реализации

Leaf tensor: тензор, созданный явно (а не результат операции). Только у leaf-тензоров есть .grad.

detach(): отсоединить от графа — обнулить requires_grad для подграфа, не пересчитывать градиенты выше этой точки.

# Если want признаки без gradients в loss
features = encoder(x).detach()  # граф оборвётся здесь
loss = classifier(features)
loss.backward()  # градиент не идёт в encoder

8. Производные высших порядков

Иногда нужны вторые производные (для Гессиана, оптимизации второго порядка, физически информированных сетей).

В PyTorch это работает через create_graph=True в .backward():

x = torch.tensor([[1.0, 2.0]], requires_grad=True)
y = (x ** 2).sum()

# Первая производная
grad1 = torch.autograd.grad(y, x, create_graph=True)[0]
# grad1 снова зависит от x и может быть дифференцирована

# Вторая производная (Гессиан диагональ)
grad2 = torch.autograd.grad(grad1.sum(), x)[0]
print(grad2)  # [2., 2.] — вторая производная x^2 это 2

Проблема: вторые производные дорогие (во фронтенде и бэкенде нужны графы). Для больших сетей нереально. Но для PINN с маленькими сетями — нормально.

9. Физически информированные сети: идея

Классическая задача: решить дифференциальное уравнение. Пример, уравнение теплопроводности:

$$ \frac{\partial u}{\partial t} = \alpha \frac{\partial^2 u}{\partial x^2}, \quad t \in [0, T], x \in [0, L] $$

С граничными условиями (BC) и начальными условиями (IC).

9.1 Классический подход: сетки

Разбить область на сетку, дискретизировать производные конечными разностями, решить систему линейных уравнений. Минусы: для высоких размерностей сетка разрастается экспоненциально (curse of dimensionality).

9.2 Идея PINN: сеть вместо сетки

Ключевая идея: вместо сетки представить решение $u(x,t)$ нейросетью $u_\theta(x,t)$. Производные $\frac{\partial u}{\partial t}$, $\frac{\partial^2 u}{\partial x^2}$ получить через автоматическое дифференцирование по входам $x,t$.

PINN архитектура x, t (координаты) │ ▼ ┌──────────────┐ │ MLP │ │ (tanh) │ u_θ = нейросеть, параметров θ └──────────────┘ │ ▼ u = u_θ(x,t) Автодифф по входу x,t: │ ├──▶ ∂u/∂t (через .grad) ├──▶ ∂u/∂x (через .grad) └──▶ ∂²u/∂x² (вторая производная) Невязка уравнения: │ ▼ ∂u/∂t - α·∂²u/∂x² = 0 Loss = невязка + граничные условия + начальные условия Сеть предсказывает решение u(x,t). Её входы — координаты. Производные вычисляем автодифференцированием. Невязка — это part of loss.

9.3 Почему это работает?

Нейросеть дифференцируема по входам (параметров!) в любой точке. Поэтому можем взять производную решения в любой точке непрерывно, не нужна сетка.

10. Loss PINN: невязка уравнения

Пусть решаем:

$$ \mathcal{L}(u) = 0 \quad (x,t) \in \Omega $$ $$ u = g \quad \text{на границе} \partial\Omega $$ $$ u = u_0 \quad \text{при } t=0 $$

где $\mathcal{L}$ — дифференциальный оператор (например, $\mathcal{L}(u) = \frac{\partial u}{\partial t} - \alpha \frac{\partial^2 u}{\partial x^2}$).

10.1 Три части loss

$$ L_{\text{total}} = L_{\text{PDE}} + \lambda_{\text{BC}} L_{\text{BC}} + \lambda_{\text{IC}} L_{\text{IC}} $$

(1) PDE loss — невязка уравнения:

$$ L_{\text{PDE}} = \frac{1}{N_f} \sum_{i=1}^{N_f} [\mathcal{L}(u_\theta(x_i, t_i))]^2 $$

Где $(x_i, t_i)$ — коллокационные точки (collocation points), случайно выбранные в области $\Omega$. Типично $N_f = 5000$–$50000$.

(2) BC loss — граничные условия:

$$ L_{\text{BC}} = \frac{1}{N_b} \sum_{i=1}^{N_b} [u_\theta(x_i^b, t_i^b) - g(x_i^b, t_i^b)]^2 $$

Граничные точки $(x_i^b, t_i^b)$ на $\partial\Omega \times [0,T]$.

(3) IC loss — начальные условия:

$$ L_{\text{IC}} = \frac{1}{N_0} \sum_{i=1}^{N_0} [u_\theta(x_i, 0) - u_0(x_i)]^2 $$

Точки $(x_i, 0)$ при $t=0$.

10.2 Числовой пример: простое ODE

Задача: решить $u'' + u = 0$ с $u(0) = 1, u'(0) = 0$ на $x \in [0, 2\pi]$.

Истинное решение: $u(x) = \cos(x)$.

Сеть: $u_\theta(x)$ — скрытая размерность 128, tanh. Loss:

$$ L = \frac{1}{5000} \sum_i (u_\theta''(x_i) + u_\theta(x_i))^2 + \lambda_0 (u_\theta(0) - 1)^2 + \lambda_1 (u_\theta'(0) - 0)^2 $$

Коллокационные точки — случайные $x \in [0, 2\pi]$. Обучаем тысячи эпох. Результат: $u_\theta$ с очень высокой точностью приближает $\cos(x)$, и это приближение гладкое в любой точке.

11. Почему tanh, а не ReLU в PINN

🎯 Частый экзаменационный вопрос

Ответ: Потому что в PINN нужны высокие производные решения (вторые, третьи…). ReLU имеет кусочно-линейную форму: первая производная = 0 или 1 (разрыва в 0), вторая производная = 0 везде (кроме точки излома). Если в PDE участвует $\frac{\partial^2 u}{\partial x^2}$, и сеть из ReLU, то вторая производная всегда нулевая, уравнение вырождается!

12. Плюсы, минусы, мини-пример кода

12.1 Плюсы PINN

  • Сетка не нужна. Можно работать в любых размерностях без проклятия размерности.
  • Гладкое решение. Нейросеть по определению гладкая, гарантировано выполняет уравнение везде, не только на сетке.
  • Смешивание физики и данных. Можно совместить PDE loss (физика) с data loss (реальные измерения): $L = L_{\text{PDE}} + \lambda L_{\text{data}}$. Отсюда название «физически информированные».
  • Обратные задачи. Если неизвестны коэффициенты уравнения (например, $\alpha$ в уравнении теплопроводности), можно их обучить как параметры сети!

12.2 Минусы PINN

  • Обучение медленное и нестабильное. Loss одновременно оптимизирует три вещи (PDE, BC, IC) с разными масштабами. Баланс $\lambda$ нужно подбирать вручную, это боль.
  • Нет гарантий. Никто не обещает, что сеть действительно решит уравнение. Нет bounds на ошибку приближения.
  • На простых 1D–2D задачах классические солверы точнее и быстрее. PINN имеет смысл для $d \geq 3$ (высокие размерности).
  • Проблемы с жёсткими задачами (stiff equations). Если уравнение имеет решения разных масштабов (быстро и медленно меняющихся), PINN сходится очень плохо.

12.3 Мини-пример: решение u'' + u = 0

import torch
import torch.nn as nn

# 1. Сеть u(x)
class PINN(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(1, 128), nn.Tanh(),
            nn.Linear(128, 128), nn.Tanh(),
            nn.Linear(128, 1)
        )

    def forward(self, x):
        return self.net(x)

    def forward_with_derivs(self, x):
        # Вычисляем u, u', u''
        x.requires_grad_(True)
        u = self.net(x)

        # Первая производная
        u_x = torch.autograd.grad(u.sum(), x, create_graph=True)[0]

        # Вторая производная
        u_xx = torch.autograd.grad(u_x.sum(), x)[0]

        return u, u_x, u_xx

# 2. Обучение
model = PINN()
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

for epoch in range(1000):
    optimizer.zero_grad()

    # Коллокационные точки
    x_f = torch.linspace(0, 2*torch.pi, 5000).view(-1, 1)
    x_f.requires_grad = True
    u_f, u_x_f, u_xx_f = model.forward_with_derivs(x_f)

    # PDE loss: u'' + u = 0
    pde_loss = ((u_xx_f + u_f) ** 2).mean()

    # Граничные условия: u(0) = 1, u'(0) = 0
    x0 = torch.tensor([[0.0]], requires_grad=True)
    u0, u0_x, _ = model.forward_with_derivs(x0)
    bc_loss = (u0 - 1) ** 2 + u0_x ** 2

    # Общая loss
    loss = pde_loss + bc_loss
    loss.backward()
    optimizer.step()

    if (epoch + 1) % 100 == 0:
        print(f"Epoch {epoch+1}: Loss = {loss.item():.6f}")

Результат: после обучения $u_\theta(x)$ приблизительно равна $\cos(x)$ на всём интервале $[0, 2\pi]$, и это приближение гладкое и удовлетворяет дифференциальному уравнению.

🎯 Препод спросит

В чём разница между символьным и автоматическим дифференцированием?

Символьное: подаём формулу в систему (SymPy), она манипулирует выражением, выводит формулу производной, потом вычисляем. Плюс — точно, минус — выражение может разрастись экспоненциально. Автодифф: разлагаем вычисление на элементарные операции, применяем цепное правило к конкретным числам во время вычисления. Точность машинная, стоимость фиксированная, не зависит от сложности формулы. Автодифф — способ индустриального стандарта в ML.

Forward vs reverse mode — когда какой использовать?

Forward mode: O(n·T) где n = число входов. Выгоден когда входов мало, выходов много. Reverse mode: O(m·T) где m = число выходов. Выгоден когда входов много, выходов мало. В нейросетях: входов тысячи/миллионы, выход = 1 скаляр loss, поэтому reverse выигрывает в миллионы раз. Reverse mode = backprop.

Почему в нейросетях используется именно reverse mode?

Потому что нужно вычислить градиент loss по всем параметрам. Параметров может быть млн, loss — один скаляр. Forward mode потребовал бы млн проходов (по одному на каждый параметр), reverse mode — один проход назад. Стоимость reverse ≈ одному forward pass, reverse в миллионы раз дешевле.

Что такое вычислительный граф и зачем его сохранять?

Вычислительный граф — это DAG (граф без циклов), где узлы = переменные, рёбра = операции. Во время forward pass PyTorch строит такой граф (динамически) и сохраняет его. При backward pass идём по графу в обратном порядке, применяя цепное правило. Граф нужен, чтобы знать, какие операции были и в каком порядке, и какие значения для них нужны.

Что такое коллокационные точки в PINN и почему их случайные?

Коллокационные точки — это точки $(x_i, t_i)$ внутри области, где проверяем, что уравнение выполняется. Типично 5000–50000 таких точек. Они случайные, потому что: (1) нет необходимости в сетке — можно брать любые точки; (2) стохастичность помогает избежать переобучения; (3) быстрее, чем регулярная сетка при высоких размерностях.

Почему в PINN нельзя использовать ReLU?

ReLU имеет вторую производную = 0 везде (кроме точки излома). Если PDE содержит $\frac{\partial^2 u}{\partial x^2}$ или выше, и $u$ реализована ReLU, то эта вторая производная всегда нулевая, уравнение вырождается в тривиальное. Нужны гладкие активации (tanh, sine, softplus) с ненулевыми производными любого порядка.

Как в PyTorch считаются вторые производные?

Использовать torch.autograd.grad с create_graph=True. Первый раз: grad1 = torch.autograd.grad(y, x, create_graph=True)[0]. Результат grad1 остаётся дифференцируемым. Второй раз: grad2 = torch.autograd.grad(grad1.sum(), x)[0]. Вторая производная в grad2. Минус: дорого по памяти и времени, так что вторые производные доступны только для малых сетей.

Что такое адъюнкт в reverse mode и как он распространяется?

Адъюнкт $\bar{z} = \frac{\partial L}{\partial z}$ для промежуточного значения z — это «сколько loss зависит от z». При reverse pass идём по графу назад и пересчитываем адъюнкты: $\bar{x} = \bar{z} \cdot \frac{\partial z}{\partial x}$ по цепному правилу. Если z зависит от нескольких x, адъюнкты суммируются. На выходе получаем $\frac{\partial L}{\partial \theta}$ для всех параметров θ.

Почему PINN медленно сходятся и как это решается?

Loss содержит три слагаемых: L_PDE, L_BC, L_IC с разными масштабами. Нужно балансировать через коэффициенты λ. Если λ неправильный, одна часть доминирует, другие зарывают. Решения: (1) Подбирать λ вручную (боль). (2) Динамическое перевзвешивание: пересчитывать λ во время обучения, давая больший вес слагаемым с большей ошибкой. (3) Использовать многозадачное обучение (multi-task learning). (4) Улучшать инициализацию весов и выбор гиперпараметров оптимизатора.

Можно ли в PINN использовать данные (обратная задача)?

Да, это основная фишка PINN. Если есть реальные измерения u_data в точках, добавляем в loss: $L = L_{\text{PDE}} + λ_d L_{\text{data}}$, где $L_{\text{data}} = \sum_i (u_\theta(x_i) - u_{\text{data}, i})^2$. Это позволяет совместить физику (уравнение должно выполняться) с данными (модель должна проходить через измерения). Отсюда и название «физически информированные» — информация одновременно от уравнения и от данных.

На каких задачах PINN выигрывает у классических солверов?

Высокие размерности (d ≥ 3), где сетка становится неприемлемо большой (проклятие размерности). Обратные задачи (искать коэффициенты уравнения по данным). Смешивание физики и данных при редких измерениях. Но на простых 1D–2D задачах классические солверы (FEM, FDM) быстрее и точнее. PINN — для специальных и трудных случаев.

📝 Микро-задачи

Задача 1. Forward mode вручную

Функция $f(x) = x^2 + e^x$. Вычисли $f(0)$ и $f'(0)$ в forward mode, используя дуальные числа.

Решение

Инициализируем: $(x, \dot{x}) = (0, 1)$.

$x^2$: $(0, 1) \times (0, 1) = (0, 0 \cdot 1 + 0 \cdot 1) = (0, 0)$.

$e^x$: $\exp(0, 1) = (e^0, e^0 \cdot 1) = (1, 1)$.

$x^2 + e^x$: $(0, 0) + (1, 1) = (1, 1)$.

Результат: $f(0) = 1$, $f'(0) = 1$. Проверка: $f'(x) = 2x + e^x$, при $x=0$: $f'(0) = 0 + 1 = 1$ ✓

Задача 2. Reverse mode вручную

Граф: $z = x + y$, $L = z^2$ с $x = 1, y = 2$. Выполни backward pass, найди $\frac{\partial L}{\partial x}$ и $\frac{\partial L}{\partial y}$.

Решение

Forward: $z = 1 + 2 = 3$, $L = 9$.

Backward: $\bar{L} = 1$ (по определению).

$\bar{z} = \frac{\partial L}{\partial z} = 2z = 6$.

$\bar{x} = \bar{z} \cdot \frac{\partial z}{\partial x} = 6 \cdot 1 = 6$.

$\bar{y} = \bar{z} \cdot \frac{\partial z}{\partial y} = 6 \cdot 1 = 6$.

Проверка: $\frac{\partial L}{\partial x} = \frac{\partial (x+y)^2}{\partial x} = 2(x+y) = 6$ ✓

Задача 3. Вторые производные в PyTorch

Функция $y = x^3$ с $x = 2$. Найди $y'$ и $y''$ используя torch.autograd.grad с create_graph=True.

Решение
import torch

x = torch.tensor(2.0, requires_grad=True)
y = x**3

# Первая производная
y_prime = torch.autograd.grad(y, x, create_graph=True)[0]
print(f"y' = {y_prime.item()}")  # 3*2^2 = 12

# Вторая производная
y_double_prime = torch.autograd.grad(y_prime, x)[0]
print(f"y'' = {y_double_prime.item()}")  # 6*2 = 12

Ожидаемо: $y' = 12$, $y'' = 12$.

Задача 4. Стоимость modes для нейросети

Нейросеть: 1000 входов, 1 млн параметров, 1 выход (loss). Во сколько раз reverse mode дешевле forward mode?

Решение

Forward mode: нужно 1000 проходов (один на каждый вход).

Reverse mode: нужно 1 проход (один на выход = loss).

Ratio: $\frac{1000}{1} = 1000$ раз дешевле.

На самом деле, дешевле ещё больше, потому что нужны градиенты по параметрам (1 млн), а не по входам.

Задача 5. Активация для PINN

Почему ReLU не подходит для PINN, где нужна $\frac{\partial^2 u}{\partial x^2}$? Что лучше использовать?

Решение

ReLU: $\text{ReLU}(z) = \max(0, z)$, первая производная = 0 или 1, вторая производная = 0 везде (кроме $z=0$).

Если $u_\theta$ построена из ReLU, то $\frac{\partial^2 u}{\partial x^2} \equiv 0$, и PDE $\mathcal{L}(u) = u'' + u = 0$ вырождается в $u = 0$, что неправильно.

Решение: использовать tanh, sin/cos (Fourier features), softplus — всё, что имеет гладкие, ненулевые производные высоких порядков.

Задача 6. Loss PINN с тремя слагаемыми

PDE: $u_t + u \cdot u_x = 0$ на $[0,1] \times [0,1]$ (x,t). BC: $u(0,t) = 0, u(1,t) = 0$. IC: $u(x,0) = \sin(\pi x)$. Запиши loss для PINN.

Решение

$$L = \frac{1}{N_f}\sum_i [u_t(x_i,t_i) + u(x_i,t_i) \cdot u_x(x_i,t_i)]^2 + \lambda_b \left[\frac{1}{N_b}\sum_i (u(0,t_i))^2 + (u(1,t_i))^2\right]$$

$$+ \lambda_0 \frac{1}{N_0}\sum_i [u(x_i,0) - \sin(\pi x_i)]^2$$

Здесь $(x_i, t_i)$ — коллокационные точки, производные $u_t, u_x$ вычисляются через autodiff.

⚡ Ответ за 3 минуты

Скелет устного ответа на билет 2 (Автодифф и PINN)
  1. Четыре способа производных. Аналитически (вручную), символьно (SymPy, выражение растёт), численно (конечные разности, ошибки округления и отсечения), автоматически (лучший способ).
  2. Автодифф суть. Разложить на элементарные операции, применить цепное правило к конкретным числам, не символам. Точность машинная, стоимость O(P).
  3. Вычислительный граф. DAG где узлы = переменные, рёбра = операции. Forward pass вычисляет и сохраняет граф. Backward идёт по графу назад, применяя цепное правило.
  4. Forward mode. Распространяем производные вперёд (дуальные числа). Стоимость O(n·T) где n = входы. Выгоден для многовыходных, маловходных задач.
  5. Reverse mode. Два прохода: forward сохраняет граф, backward пересчитывает адъюнкты. Стоимость O(m·T) где m = выходы. Выгоден для многопараметровых сетей (m=1 скаляр loss).
  6. Backprop = reverse-mode autodiff. Обратное распространение ошибки — это просто reverse mode, применённый к нейросети.
  7. PyTorch автодифф. requires_grad=True, граф строится динамически, .backward() считает градиенты, torch.autograd.grad для partial derivatives, create_graph=True для вторых производных.
  8. PINN идея. Вместо сетки для решения PDE представить решение u(x,t) нейросетью u_θ(x,t). Производные получить автодифференцированием по входам x,t.
  9. Loss PINN. Три части: невязка PDE (коллокационные точки), граничные условия (BC), начальные условия (IC). Всего L = L_PDE + λ_b L_BC + λ_0 L_IC.
  10. Активация в PINN. Только гладкие: tanh, sin, softplus. РеЛУ не подходит — вторая производная всегда 0.
  11. Плюсы PINN. Сетка не нужна, высокие размерности, можно смешивать физику и данные, обратные задачи.
  12. Минусы PINN. Медленное обучение, нестабильность, баланс λ — боль, нет гарантий, на 1D–2D классические солверы лучше.
