1. Постановка задачи Нейросетевого Машинного Перевода (NMT)

Задача машинного перевода заключается в нахождении наиболее вероятной целевой последовательности слов $Y = (y_1, \dots, y_T)$ на целевом языке при заданном входном предложении $X = (x_1, \dots, x_S)$ на исходном языке:

$$ Y^* = \arg\max_{Y} P(Y \mid X) = \arg\max_{Y} \prod_{t=1}^T P(y_t \mid y_1, \dots, y_{t-1}, X) $$ Условная авторегрессионная генерация: вероятность каждого нового слова зависит от всех сгенерированных слов и исходной фразы $X$.

2. Языковое моделирование (Language Modeling) и Перплексия (Perplexity)

Языковая модель (Language Model, LM) оценивает совместную вероятность любой цепочки слов в языке: $P(w_1, w_2, \dots, w_T) = \prod_{t=1}^T P(w_t \mid w_{\lt t})$.

Функция потерь: Cross-Entropy / NLL

$$ \text{Loss} = \text{NLL} = -\frac{1}{T} \sum_{t=1}^T \log P(w_t \mid w_1, \dots, w_{t-1}) $$

Перплексия (Perplexity, PPL) — главная внутренняя метрика LM:

$$ \text{PPL} = \exp(\text{NLL}) = \exp\left( -\frac{1}{T} \sum_{t=1}^T \log P(w_t \mid w_{\lt t}) \right) = \left( \prod_{t=1}^T \frac{1}{P(w_t \mid w_{\lt t})} \right)^{1/T} $$
💡 Интуиция перплексии

Перплексия — это эффективный размер выбора (степень неопределенности) модели. Если $\text{PPL} = 10$, это означает, что модель на каждом шаге колеблется так, будто выбирает одно верное слово из 10 равновероятных кандидатов. Идеальная модель имеет $\text{PPL} = 1.0$. Чем меньше перплексия, тем качественнее языковая модель.

3. Стратегии декодирования: Greedy Search vs Beam Search

GREEDY SEARCH (ЖАДНЫЙ ВЫБОР): Шаг 1: [Я] (p=0.7) ──▶ Шаг 2: [люблю] (p=0.9) ──▶ Шаг 3: [ИИ] (p=0.8) (Только 1 путь) BEAM SEARCH (ЛУЧЕВОЙ ПОИСК, Beam Width B = 2): Шаг 1: ┬─ [Я] (p=0.7) ──┬─ [люблю] (0.7*0.9=0.63) ──▶ [ИИ] (0.63*0.8 = 0.504) -> ВЫБРАН! └─ [Мне] (p=0.25)─┼─ [нравится] (0.25*0.9=0.225) └─ [кажется] (0.25*0.6=0.150) (Отброшен) Beam Search сохраняет $B$ наиболее вероятных гипотез на каждом шаге, предотвращая попадание в локальные тупики.
⚠️ Штраф за длину (Length Penalty) в Beam Search

Произведение вероятностей $\prod_{t=1}^T P(y_t)$ уменьшается с каждым шагом, из-за чего Beam Search стремится выдавать слишком короткие фразы. Для компенсации логарифм вероятности нормируют на длину с коэффициентом $\alpha \approx 0.6 \dots 0.8$:

$$ \text{Score}(Y) = \frac{\sum_{t=1}^T \log P(y_t \mid y_{\lt t}, X)}{\left( \frac{5 + T}{6} \right)^\alpha} $$

4. Стохастическое сэмплирование: Temperature, Top-$k$, Top-$p$

Для творческой генерации (чат-боты, сторителлинг) детерминированный поиск приводит к унылым повторениям. Используют сэмплирование:

1. Температура ($T > 0$):

$$ P(w_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)} $$ $T \to 0$ — превращается в Greedy Search. $T = 1.0$ — стандартные вероятности. $T > 1.0$ — «нагрев» распределения (сглаживание пиков, рост креативности).

2. Top-$k$ Sampling (Fan et al., 2018):

Оставляем только $k$ самых вероятных токенов (например, $k=50$), отсекая длинный «хвост» бредовых слов. Вероятности оставшихся $k$ слов перенормируются.

3. Top-$p$ (Nucleus Sampling, Holtzman et al., 2019):

Вместо фиксированного числа слов берем минимальное множество токенов, чья суммарная накопленная вероятность превышает порог $p$ (например, $p=0.9$). На простых шагах пул сжимается до 1–2 уверенных слов, на сложных — расширяется до сотен.

5. Метрика BLEU (Bilingual Evaluation Understudy)

Разработанная в IBM (Papineni et al., 2002), BLEU — главная историческая метрика автоматической оценки машинного перевода по сравнению с человеческими референсами.

$$ \text{BLEU} = \text{BP} \cdot \exp\left( \sum_{n=1}^N w_n \log p_n \right) $$ Обычно берут $N=4$ ($1, 2, 3, 4$-граммы) с равными весами $w_n = 1/4 = 0.25$.

Компоненты формулы BLEU:

  1. Модифицированная точность $n$-грамм ($p_n$): Доля $n$-грамм гипотезы, встречающихся в референсе, причем каждое вхождение засчитывается не более максимального числа раз, встреченного в эталоне (Clipping Count, защита от спама одного слова).
  2. Штраф за краткость (Brevity Penalty, BP): Защита от коротких переводов из одного слова (у которых $p_1 = 100\%$): $$ \text{BP} = \begin{cases} 1, & \text{если } c > r \\ \exp\left(1 - \frac{r}{c}\right), & \text{если } c \le r \end{cases} $$ где $c$ — длина сгенерированного перевода (Candidate), $r$ — длина эталона (Reference).

7. Пошаговый расчет BLEU вручную на примере

Эталон (Reference, $r=6$): «the cat is on the mat» (длина $r=6$).
Кандидат (Candidate, $c=4$): «the the the mat» (длина $c=4$).

  1. Точность униграмм ($p_1$):
    • Слово «the» встретилось в кандидате 3 раза. В референсе — максимум 2 раза. Клиппинг: $\text{Count}_{\text{clip}}(\text{«the»}) = 2$.
    • Слово «mat» встретилось 1 раз. В референсе — 1 раз. $\text{Count}_{\text{clip}}(\text{«mat»}) = 1$.
    • $$ p_1 = \frac{2 + 1}{4} = \frac{3}{4} = 0.75 $$
  2. Точность биграмм ($p_2$):
    • Биграммы кандидата: «the the», «the the», «the mat».
    • В референсе биграмма «the the» отсутствует (0). Биграмма «the mat» присутствует (1).
    • $$ p_2 = \frac{0 + 0 + 1}{3} = \frac{1}{3} \approx 0.333 $$
  3. Штраф за краткость (BP):

    Так как $c = 4 < r = 6$:

    $$ \text{BP} = \exp\left(1 - \frac{6}{4}\right) = \exp(-0.5) \approx 0.6065 $$
  4. Итоговый BLEU-2: $$ \text{BLEU-2} = 0.6065 \cdot \exp\left( 0.5 \ln 0.75 + 0.5 \ln 0.333 \right) = 0.6065 \cdot \sqrt{0.75 \cdot 0.333} = 0.6065 \cdot 0.50 \approx 0.303 \quad (30.3\%) $$

8. Практическая реализация на Python

import math
from collections import Counter

def calculate_bleu(reference, candidate, max_n=4):
    ref_tokens = reference.split()
    cand_tokens = candidate.split()
    c = len(cand_tokens)
    r = len(ref_tokens)
    
    if c == 0: return 0.0
    
    # 1. Brevity Penalty
    bp = 1.0 if c > r else math.exp(1 - r / c)
    
    # 2. Modified n-gram precisions
    log_precisions = []
    for n in range(1, max_n + 1):
        cand_ngrams = [tuple(cand_tokens[i:i+n]) for i in range(len(cand_tokens) - n + 1)]
        ref_ngrams = [tuple(ref_tokens[i:i+n]) for i in range(len(ref_tokens) - n + 1)]
        
        cand_counts = Counter(cand_ngrams)
        ref_counts = Counter(ref_ngrams)
        
        clipped_matches = sum(min(count, ref_counts[ng]) for ng, count in cand_counts.items())
        total_ngrams = max(len(cand_ngrams), 1)
        
        p_n = clipped_matches / total_ngrams
        if p_n == 0:
            return 0.0 # Если хотя бы одна точность 0, геометрическое среднее зануляется
        log_precisions.append(math.log(p_n))
        
    score = bp * math.exp(sum(log_precisions) / max_n)
    return score

🎯 Препод спросит

Что такое Перплексия (Perplexity) и как она связана с кросс-энтропией?

Перплексия — это экспонента от усредненных кросс-энтропийных потерь модели на тестовой выборке: $\text{PPL} = \exp(\text{CrossEntropyLoss})$. Интуитивно она показывает эффективное число слов, среди которых колеблется модель на каждом шаге предсказания. Чем ниже PPL, тем более уверена и точна языковая модель.

Зачем в BLEU введен Brevity Penalty (штраф за краткость)?

Без Brevity Penalty модель могла бы перевести сложный абзац одним словом «the», получив точность $p_1 = 100\%$ и идеальный балл BLEU. BP экспоненциально штрафует модель, если сгенерированный текст $c$ короче эталона $r$ ($\text{BP} = \exp(1 - r/c)$), заставляя переводить предложение полностью.

В чем фундаментальный недостаток метрики BLEU?

BLEU сравнивает только точное лексическое совпадение $n$-грамм. Если модель использовала корректный синоним (например, «автомобиль» вместо «машина») или перефразировала мысль другими словами, BLEU поставит 0 баллов за эту фразу. Для решения этой проблемы созданы метрики на эмбеддингах — BERTScore и COMET.

Чем Top-$p$ (Nucleus) сэмплирование лучше Top-$k$ сэмплирования?

В Top-$k$ размер пула фиксирован (например, всегда 50 слов). Если следующее слово очевидно (например, после «Президент Соединенных...» слово «Штатов» имеет вероятность 99%), Top-$k$ все равно добавит в пул 49 маловероятных слов и может случайно выбрать бред. Top-$p$ адаптивно сузит пул до одного слова. Когда контекст неоднозначен, Top-$p$ динамически расширит пул кандидатов.

Как параметр температуры $T$ влияет на логиты перед Softmax?

Логиты делятся на скаляр $T$: $z_i / T$. При $T < 1.0$ разница между логитами усиливается, Softmax становится резким и острым (детерминированный выбор). При $T > 1.0$ значения логитов сближаются, распределение Softmax становится плоским и близким к равномерному (максимальная случайность и разнообразие).

В чем разница между BLEU и ROUGE?

BLEU ориентирован на Precision (Точность): сколько сгенерированных слов было в эталоне (важно для перевода, чтобы не выдумывать лишнего). ROUGE ориентирован на Recall (Полноту): сколько ключевых фактов эталона модель смогла охватить (важно для суммаризации, чтобы не упустить суть).

Как математически вычисляется модифицированная точность $n$-грамм (Modified $n$-gram Precision) в BLEU и почему простой подсчет совпадений неприменим?

Обычная точность делит число совпавших $n$-грамм на общее число $n$-грамм в гипотезе. Если модель сгенерирует патологическую строку «the the the the the», а в эталоне содержится «the cat is on the mat» (где слово «the» встречается 2 раза), стандартная точность униграмм составит $\frac{5}{5} = 1.0$ ($100\%$).

Для устранения этой уязвимости Papineni et al. (2002) ввели клиппинг (усечение) счетчиков по максимальному числу вхождений в любой из эталонов:

$$ \text{Count}_{\text{clip}}(\text{n-gram}) = \min\left(\text{Count}_{\text{cand}}(\text{n-gram}),\; \max_{r \in R} \text{Count}_r(\text{n-gram})\right) $$

где $R$ — множество референсных переводов. Корпусная модифицированная точность порядка $n$ вычисляется как:

$$ p_n = \frac{\sum_{C \in \{\text{Candidates}\}} \sum_{\text{n-gram} \in C} \text{Count}_{\text{clip}}(\text{n-gram})}{\sum_{C \in \{\text{Candidates}\}} \sum_{\text{n-gram} \in C} \text{Count}_{\text{cand}}(\text{n-gram})} $$

В примере выше $\text{Count}_{\text{cand}}(\text{"the"}) = 5$, $\text{Count}_{\text{ref}}(\text{"the"}) = 2 \implies \text{Count}_{\text{clip}} = \min(5, 2) = 2$, и точность $p_1 = \frac{2}{5} = 0.4$, что надежно штрафует вырожденные повторения.

Какова строгая формула Brevity Penalty (BP) в BLEU и как ведет себя штраф при $c < r$ против $c \ge r$?

Формула Brevity Penalty имеет вид:

$$ \text{BP} = \begin{cases} 1, & \text{если } c > r \\ \exp\left(1 - \frac{r}{c}\right), & \text{если } c \le r \end{cases} $$

где $c$ — длина перевода кандидата (в токенах), $r$ — эффективная длина эталона.

  • При $c > r$ (кандидат длиннее эталона): $\text{BP} = 1.0$. Избыточная длина не штрафуется через BP, так как длинный перевод автоматически штрафуется в знаменателе точности $p_n$ из-за появления лишних $n$-грамм, отсутствующих в эталоне.
  • При $c \le r$ (кандидат короче эталона): $\text{BP} = \exp\left(1 - \frac{r}{c}\right) \le 1.0$. Экспоненциальный штраф компенсирует то, что короткие фразы искусственно завышают точность $p_n$. При $c \to 0$ показатель степени $1 - \frac{r}{c} \to -\infty$, следовательно $\text{BP} \to 0$, что обнуляет итоговый BLEU для пустых или обрезанных переводов.
В чем преимущества метрик chrF, BERTScore и COMET по сравнению с классическим BLEU?

Классический BLEU опирается на строгое совпадение точных $n$-грамм токенов, что создает проблемы с синонимией, морфологией и перефразированием. Современные метрики решают эти проблемы:

  • chrF (Character $F$-score): Оценивает совпадение символьных $n$-грамм (обычно от 1 до 6 символов). Крайне эффективна для синтетических и флективных языков с развитой морфологией (например, русского), так как совпадение корней и основ слов засчитывается даже при различии падежных окончаний.
  • BERTScore: Вычисляет попарное косинусное сходство между контекстуализированными эмбеддингами токенов кандидата и эталона с помощью предобученной модели (BERT/RoBERTa) с жадным сопоставлением. Учитывает семантическую близость синонимов и устойчив к перестановке слов.
  • COMET (Crosslingual Optimized Metric for Evaluation of Translation): Нейросетевая модель на базе энкодера XLM-RoBERTa, принимающая на вход одновременно исходный текст (source), гипотезу (hypothesis) и эталон (reference). Обучается напрямую на оценках экспертов-лингвистов (MQM, Direct Assessment) и обладает максимальной корреляцией с человеческим восприятием качества перевода.
Почему Beam Search без нормализации штрафует длинные гипотезы и как работает формула Length Normalization $LP(Y) = \frac{(5+|Y|)^\alpha}{(5+1)^\alpha}$?

В авторегрессионных моделях логарифмическая вероятность генерации последовательности $Y = (y_1, \dots, y_{|Y|})$ вычисляется как сумма:

$$ \log P(Y \mid X) = \sum_{t=1}^{|Y|} \log P(y_t \mid y_{< t}, X) $$

Поскольку $P(y_t) \le 1$, все логарифмические слагаемые неположительны ($\log P(y_t) \le 0$). С каждым следующим токеном сумма монотонно убывает (становится более отрицательной). В результате стандартный Beam Search систематически отдает предпочтение коротким гипотезам, которые быстрее сгенерировали специальный токен окончания последовательности <EOS>.

Для устранения этой асимметрии Wu et al. (2016) ввели нормализацию по длине (Length Penalty):

$$ LP(Y) = \frac{(5 + |Y|)^\alpha}{(5 + 1)^\alpha}, \qquad \text{Score}(Y \mid X) = \frac{\log P(Y \mid X)}{LP(Y)} $$

где $|Y|$ — число токенов, а $\alpha \in [0.6, 0.8]$ — коэффициент компенсации:

  • Константа $5$ сглаживает штраф для первых нескольких токенов, предотвращая завышение ранга сверхкоротких кандидатов.
  • Делитель $(5+1)^\alpha$ нормирует $LP(Y) = 1$ при единичной длине $|Y|=1$.
  • Параметр $\alpha$ регулирует силу компенсации: при $\alpha=0$ штраф выключен, при $\alpha=1$ выполняется полная нормировка на среднюю лог-вероятность.

📝 Микро-задачи

Задача 1. Расчет Перплексии по потерям

Языковая модель показала усредненный лосс кросс-энтропии $\text{NLL} = 2.3026$ (натуральный логарифм). Чему равна Перплексия модели?

Решение

$$ \text{PPL} = \exp(2.3026) = e^{2.3026} \approx 10.0 $$

Модель выбирает следующее слово с уверенностью, эквивалентной выбору из 10 равновероятных слов.

Задача 2. Расчет Brevity Penalty

Длина эталона $r = 20$ слов, длина перевода модели $c = 15$ слов. Рассчитайте коэффициент Brevity Penalty.

Решение

Так как $c < r$:

$$ \text{BP} = \exp\left(1 - \frac{20}{15}\right) = \exp\left(1 - 1.333\right) = \exp(-0.333) \approx 0.7165 $$

Итоговый скор BLEU будет уменьшен почти на $28\%$ из-за неполноты длины.

Задача 3. Ручной расчет Top-p (Nucleus) пула

Словарь и вероятности: $w_1: 0.50$, $w_2: 0.25$, $w_3: 0.15$, $w_4: 0.07$, $w_5: 0.03$. Задан порог $p = 0.85$. Какие слова войдут в ядро Nucleus?

Решение

Считаем накопленную (кумулятивную) сумму вероятностей по убыванию:

  • $w_1$: $0.50 \le 0.85$ (берем). Накоплено: 0.50.
  • $w_2$: $0.50 + 0.25 = 0.75 \le 0.85$ (берем). Накоплено: 0.75.
  • $w_3$: $0.75 + 0.15 = 0.90 \ge 0.85$ (берем и останавливаемся, порог $0.85$ достигнут!).

В ядро войдут слова: $\{w_1, w_2, w_3\}$. Слова $w_4$ и $w_5$ отсекаются.

Задача 4. Влияние температуры на вероятности

Логиты двух токенов: $z_1 = 4.0, z_2 = 2.0$. Найдите вероятность $P(w_1)$ при: (а) $T=1.0$; (б) $T=2.0$.

Решение

(а) При $T=1.0$:

$P(w_1) = \frac{e^4}{e^4 + e^2} = \frac{54.6}{54.6 + 7.39} = \frac{54.6}{61.99} \approx 0.881 \quad (88.1\%)$.

(б) При $T=2.0$:

Логиты делятся на 2: $z_1' = 2.0, z_2' = 1.0$.

$P(w_1) = \frac{e^2}{e^2 + e^1} = \frac{7.39}{7.39 + 2.72} = \frac{7.39}{10.11} \approx 0.731 \quad (73.1\%)$.

Повышение температуры снизило доминирование лидера с 88.1% до 73.1%.

Задача 5. Геометрическое зануление BLEU

Перевод модели: $p_1 = 0.8, p_2 = 0.6, p_3 = 0.4, p_4 = 0.0$. Чему равен классический BLEU-4?

Решение

В формуле BLEU используется геометрическое среднее: $\exp\left(\frac{1}{4} \sum \ln p_n\right) = (p_1 p_2 p_3 p_4)^{1/4}$.

Так как $p_4 = 0.0$, то $(0.8 \cdot 0.6 \cdot 0.4 \cdot 0.0)^{1/4} = 0.0$.

$$ \text{BLEU-4} = 0.0 $$

Примечание: В современных библиотеках (SacreBLEU) для коротких фраз применяют сглаживание (Smoothing), заменяя $0$ на малое значение $\epsilon$.

Задача 6. Сравнение Beam Search с шириной B=1 и B=4

Пусть словарь $|V| = 32\,000$, длина генерации $T = 50$. Сколько вызовов модели на шаг требуется при Greedy Search ($B=1$) и Beam Search ($B=4$)?

Решение

При $B=1$: на каждом шаге обрабатывается 1 гипотеза $\to 50$ прогонов декодера.

При $B=4$: на каждом шаге обрабатывается $B=4$ гипотезы параллельно (размер батча 4) $\to 4 \times 50 = 200$ прогонов.
