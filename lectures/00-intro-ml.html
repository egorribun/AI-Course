1. Общая картина: задача ML

Машинное обучение — это не магия. Это ответ на простейший вопрос: у нас есть примеры, как вывести правило?

У вас есть 1000 писем: 700 спама, 300 нормальных. Внутри каждого письма — слова. Вопрос: можно ли научить компьютер отличать спам от не-спама, не написав правила вручную?

Оказывается, можно. Не потому что компьютер станет умнее, а потому что мы научимся параметризовать решение: придумаем семейство функций, зависящих от чисел (параметров), и подберём эти числа так, чтобы функция хорошо разделяла примеры.

💡 Фундамент всего курса

Машинное обучение = поиск параметризованной функции $f_\theta$, которая на обучающих примерах даёт ответы, близкие к истине.

Три вопроса:

  • Какое семейство функций? (архитектура: нейросеть, дерево решений, линейная модель…)
  • Как измеряем «ошибку»? (loss-функция: MSE, cross-entropy…)
  • Как подбираем параметры? (оптимизация: градиентный спуск, случайный поиск…)

Если вы помните эту триаду на всех экзаменах, вы сможете рассуждать логично о любой современной архитектуре — CNN, Transformer, GAN, всё будет слагаться в единую картину.

2. Три парадигмы: обучение с учителем, без учителя, с подкреплением

2.1 Обучение с учителем (Supervised Learning)

Есть: выборка пар (вход, истинный выход): $\{(x_i, y_i)\}_{i=1}^N$.

Цель: научить модель предсказывать $y$ по $x$.

Две подзадачи:

  • Регрессия: выход $y$ — число (цена дома, температура, зарплата). Предсказываем вещественное значение.
  • Классификация: выход $y$ — номер класса (кошка/собака/птица, спам/не спам). Предсказываем метку из конечного набора.
ОБУЧЕНИЕ С УЧИТЕЛЕМ ┌─────────────────────┐ │ выборка (x_i, y_i)│ └──────────┬──────────┘ │ ┌────▼─────┐ │ Функция │ ────│ f_θ │─── Предсказание y_pred │ │ └──────────┘ │ ┌────▼────────────┐ │ Loss L(y,y_pred) │ ◄── считаем ошибку └────┬─────────────┘ │ ┌────▼──────────────────┐ │ Обновить θ: │ │ θ ← θ - η·∂L/∂θ │ └────────────────────────┘ Цикл обучения с учителем: данные → модель → loss → градиент → обновление. Повторяем много раз.

2.2 Обучение без учителя (Unsupervised Learning)

Есть: только входы $\{x_i\}_{i=1}^N$, нет меток $y$.

Цель: найти скрытую структуру, паттерны, группировки.

Типичные задачи:

  • Кластеризация: разбить точки на $k$ групп (k-means, DBSCAN, иерархическая кластеризация).
  • Снижение размерности: представить высокомерные данные в низком числе измерений (PCA, t-SNE, VAE).
  • Восстановление распределения: научиться генерировать новые примеры, похожие на обучающие (GAN, VAE, диффузионные модели).
ОБУЧЕНИЕ БЕЗ УЧИТЕЛЯ ┌─────────────────┐ │ выборка x_i │ └────────┬────────┘ │ ┌────▼──────────────┐ │ Функция f_θ │ │ (кластеризация, │ Выход: кластеры, │ снижение размер- │ представление, │ ности, генерация) │ новые примеры └────┬───────────────┘ │ ┌────▼────────────────────┐ │ Loss (нет меток!): │ │ - реконструкция │ │ - контрастные пары │ │ - информационная мера │ └────┬────────────────────┘ │ ┌────▼──────────────────────┐ │ Обновить θ │ └───────────────────────────┘ Без меток нужна хитрая loss-функция, которая отражает желаемую структуру данных.

2.3 Обучение с подкреплением (Reinforcement Learning)

Есть: агент, окружение, действия и награды.

Цель: научить агента выбирать действия, которые максимизируют накопленную награду.

Ключевое отличие: нет заранее известного «правильного ответа». Агент сам экспериментирует, получает награду/штраф и учится.

Примеры: игры (Atari, Go, шахматы), робот манипулятор, беспилотный автомобиль.

ОБУЧЕНИЕ С ПОДКРЕПЛЕНИЕМ ┌────────────────┐ │ Агент │ │ (нейросеть) │ └────────┬───────┘ │ Действие a_t ▼ ┌────────────────┐ │ Окружение │ │ (среда) │ └────────┬───────┘ │ Наблюдение o_t + Награда r_t ▼ ┌────────────────────────────┐ │ Накопить опыт: (s,a,r,s') │ │ Вычислить целевое значение │ │ Обновить policy/value │ └────────────────────────────┘ Цикл: агент действует → окружение отвечает → опыт накапливается → модель обновляется.

3. Выборка: train, val, test и утечка данных

Одна из самых частых ошибок новичков: переобучение на всех данных, включая тестовые. Это мертворождённый результат.

💡 Магический раздел данных

Всю выборку из $N$ примеров делим на три непересекающихся части:

  • Train (60–80%): на этом обучаем модель. Модель видит эти примеры много раз.
  • Validation (10–20%): эти примеры модель видит, но не обучается на них. Используем для выбора гиперпараметров, ранней остановки, выбора архитектуры.
  • Test (10–20%): заключённый в золото сундук. Смотрим на него ровно один раз в конце, чтобы сообщить финальную метрику. Ни для чего больше не используем.

(60%) (15%) (25%) │ │ │ │ Обучение │ Выбор гипер- │ │ │ параметров │ └──────┤ │ ▼ │ Метрика val │ Лучшая модель? │ │ └─────────────┘ │ Финальная проверка │ ▼ Test метрика (только один раз!) Data split. Test смотрим один раз — после того как все гиперпараметры выбраны.

3.1 Что такое утечка данных (Data Leakage)?

Информация из тестовой выборки (или валидационной) просочилась в обучение. Результат: метрика на тесте нереалистично хороша, в боевых условиях модель падает.

Примеры утечек:

  1. Нормализация на всей выборке. Правильно: вычислить среднее и std на train, применить к val/test. Неправильно: вычислить на train+val+test — информация о scale распределения утекла из тестовой части в обучение.
  2. Выбор признаков на всей выборке. Нельзя делать feature selection на train+val, потом оценивать на тесте. Выбор признаков — часть обучения, он тоже должен происходить на тренировочных данных.
  3. Временные ряды: если данные упорядочены по времени, нельзя брать train и test вразнобой. Train должен быть раньше test — иначе модель видит будущее!
  4. Дублирующиеся примеры. Если один пример есть в train и test (опечатка в логике разбиения), это тоже утечка.
⚠️ Data leakage — врущая метрика

Сообщить на конференции результат с утечкой — это репутационный убой. Всегда проверяй:

  • Нормализация: scale/mean параметры вычислены только на train?
  • Feature engineering: новые признаки строились только на train?
  • Выбор гиперпараметров: происходил на val, а не на test?
  • Данные упорядочены по времени? Test должен быть позже train.

4. Недообучение, переобучение, bias-variance tradeoff

Модель может ошибаться по двум причинам:

💡 Две причины ошибки

Bias (смещение): модель слишком простая, не может выразить истинную зависимость. Пример: строим линию через данные, которые явно квадратичные. Даже на бесконечной выборке ошибка не упадёт.

Variance (дисперсия): модель слишком сложная, чувствительна к шуму в конкретной выборке. На другой похожей выборке результат будет совсем другой. Пример: полином степени 50 через 10 точек.

4.1 Недообучение (Underfitting)

Ситуация: большой bias, маленькая variance. Модель слишком простая, даже на train-данных ошибка высокая.

Симптомы:

  • Loss на train медленно снижается и застревает на высоком уровне.
  • Loss на train ≈ Loss на val (оба значения высоки).
  • Модель просто не учится.

Лечение: сделать модель сложнее (больше параметров, глубже сеть, лучше признаки), обучать дольше, улучшить данные.

4.2 Переобучение (Overfitting)

Ситуация: маленький bias, большая variance. Модель выучила train-данные включая шум, но на новых данных плохо.

Симптомы:

  • Loss на train упал очень низко (близко к нулю).
  • Loss на val > Loss на train, и зазор растёт.
  • На test метрика хуже, чем ожидаешь из val.

Лечение: регуляризация (L1/L2, dropout), больше данных, рано остановиться, сделать модель проще.

4.3 Bias-Variance Tradeoff — кривые обучения

Как растут ошибки в зависимости от сложности модели? Или от количества данных?

Ошибка vs Сложность модели (для фиксированного объёма данных) Loss│ │ train loss │ ╱ │ ╱─────╯ │ ╲──────╯ │ ╲ ╱──────────── Underfitting Overfitting │ ╲╱ │ ╱╲ │ ╱ ╲ │ ╱ ╲────╲ val loss │ ╱ ╲────╲ │ ╱ ╲╲ └──────────────────────────────────────────── простая сложная модель модель ↑ Оптимум Тренировочная ошибка монотонно падает (модель больше запоминает). Валидационная ошибка сначала падает, потом растёт (переобучение). Оптимум в точке баланса.

Числовой пример: допустим истинная функция $y = 2x + 1 + \varepsilon$, где $\varepsilon \sim N(0, 1)$.

  • Модель 1 (линейная y = ax): даже бесконечно много данных не помогут — bias. Loss → 1 (только шум).
  • Модель 2 (линейная y = ax + b): почти идеальна. Loss → 1 (шум).
  • Модель 3 (полином степени 10): с 10 точками — переобучение, variance. С 1000 точками — bias ≈ 0 (полином почти линейный), variance маленькая. Loss ≈ 1.

5. Параметры vs гиперпараметры

Параметры θ: числа внутри модели, которые обучаются на основе данных.

  • Веса нейросети $w_{ij}$.
  • Смещения bias $b_i$.
  • Коэффициенты линейной регрессии.

Мы ищем оптимальные параметры методом градиентного спуска.

Гиперпараметры: настройки алгоритма обучения, которые мы выбираем вручную (или через поиск).

  • Скорость обучения η (learning rate).
  • Размер батча (batch size).
  • Число эпох (epochs).
  • Архитектура (число слоёв, ширина).
  • Коэффициент регуляризации λ.
  • Тип оптимизатора (SGD, Adam, RMSprop).

Гиперпараметры подбираем через перебор, grid search, случайный поиск или Bayesian optimization на валидационной выборке.

⚠️ Не путай!

Параметры: числа, которые модель вычисляет сама из данных.

Гиперпараметры: числа, которые мы выбираем и передаём модели.

На экзамене: если препод спрашивает «какие параметры вашей модели?» — отвечай про $w$, $b$, не про learning rate.

6. Градиентный спуск и скорость обучения

6.1 Идея: спуск по склону в тумане

Представь себя альпинистом на горе в густом тумане. Ты хочешь спуститься вниз (минимизировать высоту — потери $L$). Видишь только землю у своих ног (градиент $\nabla L$). Как действовать?

Логично: оглянись вокруг, найди направление вниз, сделай шаг туда. Повтори много раз. Это — градиентный спуск.

6.2 Формула

$$ \theta \leftarrow \theta - \eta \nabla L(\theta) $$ $\theta$ — параметры, $\eta$ — скорость обучения, $\nabla L$ — градиент loss-функции

На каждом шаге делаем шаг в направлении наискорейшего спуска (антиградиента) с размером шага $\eta$.

Нужен goldilocks η.

6.4 Числовой пример

Функция: $L(\theta) = (\theta - 3)^2$. Минимум при $\theta = 3$. Стартуем с $\theta_0 = 0$. Градиент $\nabla L = 2(\theta - 3)$.

  • $\eta = 0.1$: $\theta_0 = 0 \to \theta_1 = 0 - 0.1 \cdot 2(-3) = 0.6 \to \theta_2 = 0.6 - 0.1 \cdot 2(-2.4) = 1.08 \to \ldots \to 3.0$ (мягкое приближение).
  • $\eta = 0.5$: $\theta_0 = 0 \to \theta_1 = 0 - 0.5 \cdot (-6) = 3$ (попали с первого шага, повезло!).
  • $\eta = 1.1$: $\theta_0 = 0 \to \theta_1 = 0 - 1.1 \cdot (-6) = 6.6 \to \theta_2 = 6.6 - 1.1 \cdot 2(3.6) = -1.92 \to$ (прыгает туда-сюда, не сходится).

На практике часто используют адаптивные оптимизаторы (Adam, RMSprop), которые сами подбирают эффективный $\eta$ для каждого параметра — об этом в лекции 6.

7. Эпоха, батч, итерация

Три слова, которые студенты частенько путают. Разберёмся.

💡 Точные определения

Итерация (iteration): один шаг градиентного спуска на одном батче. Обновляем параметры один раз.

Батч (batch): подмножество обучающей выборки, которое обрабатывается за одну итерацию. Размер батча — гиперпараметр.

Эпоха (epoch): один полный проход по всей обучающей выборке. Если выборка разбита на батчи, то одна эпоха = много итераций.

7.1 Числовой пример

Обучающая выборка: 10000 примеров. Размер батча: 100. Планируем обучение на 10 эпох.

  • Одна эпоха обработает: 10000 / 100 = 100 итераций.
  • Всего итераций: 100 итераций × 10 эпох = 1000 итераций.
  • Одна итерация: forward pass на 100 примерах, backward pass, обновление параметров.

7.2 Батчирование: зачем нужно?

Плюсы:

  • Параллелизм: GPU обрабатывает сразу 100–1000 примеров одновременно, получается ~10x дешевле, чем 100 раз по одному примеру.
  • Стабильность градиента: градиент на батче — это среднее градиентов по примерам. Средняя величина менее шумная, чем отдельный пример.
  • Регуляризация: батч-шум сам по себе помогает избежать переобучения.

Минусы: очень большой батч может привести к застреванию в плохих локальных минимумах (не хватает стохастичности).

Правило большого пальца: батч от 32 до 256 — хороший выбор. Для огромных моделей могут быть 1024–2048.

8. Метрики классификации: accuracy, precision, recall, F1, ROC-AUC

Loss-функция (MSE, cross-entropy) — это то, что мы оптимизируем. Но метрика — это то, что мы смотрим в конце, чтобы понять, хорошо ли работает модель.

8.1 Матрица ошибок (Confusion Matrix)

Рассмотрим бинарную классификацию (спам / не спам). Модель выдаёт binary prediction: 0 или 1. Реальный ответ: 0 или 1. Есть четыре исхода:

Истина
Позитив (1)Негатив (0)
ПредсказаниеПозитив (1)TP (True Positive)
Спам, правильно		FP (False Positive)
Не спам, а мы сказали спам
Негатив (0)FN (False Negative)
Спам, но мы не заметили		TN (True Negative)
Не спам, правильно

8.2 Основные метрики

$$ \text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN} \quad \text{— доля правильных ответов} $$ $$ \text{Precision} = \frac{TP}{TP + FP} \quad \text{— из предсказанных как спам, сколько на самом деле спам} $$ $$ \text{Recall} = \frac{TP}{TP + FN} \quad \text{— из реального спама, сколько мы поймали} $$ $$ \text{F1} = 2 \cdot \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} \quad \text{— гармоническое среднее}$$

8.3 Когда какую метрику использовать?

Accuracy: если классы сбалансированы (примерно поровну позитивов и негативов). Если классы дисбалансированы, accuracy врёт!

Precision: когда ложный позитив дорогой. Пример: фильтр спама. Лучше пропустить спам (FN), чем удалить нормальное письмо (FP). Ты хочешь быть уверен, что письмо действительно спам, прежде чем его удалить.

Recall: когда ложный негатив дорогой. Пример: диагностика болезни. Лучше сказать, что болезнь есть, но она не подтвердится (FP), чем пропустить болезнь (FN). Не нельзя мисс.

F1: когда оба типа ошибок одинаково плохи, и классы дисбалансированы.

8.4 Числовой пример: почему accuracy врёт при дисбалансе

Выборка: 990 не-спама, 10 спама (дисбаланс 99:1). Модель выучилась говорить: «Всё не спам».

  • TP = 0, FN = 10 (пропустили 10 спамов)
  • TN = 990, FP = 0 (правильно определили не-спам)
  • Accuracy = (0 + 990) / 1000 = 99% ← Выглядит отлично!
  • Precision = 0 / (0 + 0) = undefined ← Модель не предсказала ни одного спама.
  • Recall = 0 / (0 + 10) = 0% ← Не поймали ни одного спама!
  • F1 = 0 ← Наказано справедливо.

Вывод: при дисбалансе смотри Precision, Recall, F1, ROC-AUC — не Accuracy.

8.5 ROC-AUC

ROC-кривая показывает trade-off между TPR (recall) и FPR (ложный позитив rate): $FPR = FP / (FP + TN)$.

AUC (Area Under Curve) — площадь под этой кривой. AUC = 1 идеально, AUC = 0.5 как случайное гадание.

Плюс ROC-AUC: не зависит от выбора порога вероятности. Если модель выдаёт вероятность $p$, то порог (классифицируем как спам если $p > 0.5$) можно выбирать гибко.

9. Метрики регрессии: MSE, MAE, R²

Здесь выход $y \in \mathbb{R}$ — вещественное число, не класс.

9.1 Mean Squared Error (MSE)

$$ \text{MSE} = \frac{1}{N} \sum_{i=1}^{N} (y_i - \hat{y}_i)^2 $$

Плюсы: гладкая, дифференцируема, стандартная.

Минусы: единицы в квадрате (если $y$ — метры, MSE в м²), чувствительна к выбросам.

9.2 Mean Absolute Error (MAE)

$$ \text{MAE} = \frac{1}{N} \sum_{i=1}^{N} |y_i - \hat{y}_i| $$

Плюсы: в тех же единицах что исходные данные, робустна к выбросам.

Минусы: не дифференцируема в нуле (на практике не мешает), гиперболическая кривая.

9.3 R² (коэффициент детерминации)

$$ R^2 = 1 - \frac{\sum_i (y_i - \hat{y}_i)^2}{\sum_i (y_i - \bar{y})^2} $$ $\bar{y}$ — среднее значение $y$ по выборке

Смысл: доля дисперсии в $y$, объяснённая моделью. $R^2 = 1$ — идеально, $R^2 = 0$ — модель не лучше, чем просто предсказывать среднее, $R^2 < 0$ — модель хуже среднего (произошла беда).

10. Регуляризация: L1/L2, dropout, early stopping

Как бороться с переобучением? Вот три классических приёма.

10.1 L2-регуляризация (Ridge)

$$ L_{\text{total}} = L_{\text{data}} + \lambda \sum_i w_i^2 $$

Идея: добавляем штраф за большие веса. Модель предпочтёт маленькие веса, которые означают гладкую функцию, менее склонную переобучиться.

Эффект: веса стягиваются к нулю, но редко точно обнуляются.

10.2 L1-регуляризация (Lasso)

$$ L_{\text{total}} = L_{\text{data}} + \lambda \sum_i |w_i| $$

Идея: штраф пропорционален абсолютному значению веса.

Эффект: многие веса обнуляются полностью → sparse representation, естественный feature selection.

10.3 Dropout

На каждой итерации случайно выключаем $p$ fraction нейронов (обычно $p = 0.5$). На инференсе все нейроны активны, но веса масштабируются на $(1-p)$.

Эффект: сеть не может больше переобучиться, полагаясь на цепочку из нескольких нейронов. Как бы ансамбль.

10.4 Early Stopping

Во время обучения мониторим loss на валидационной выборке. Как только loss на val перестал улучшаться (начал расти) — останавливаем обучение, сохраняем модель из точки минимума val loss.

Эффект: поймали момент, когда модель начала переобучаться, не дали ей погрузиться ещё глубже.

🎯 Препод спросит

Чем обучение с учителем отличается от без учителя?

При обучении с учителем есть пары (вход, истинный выход), и мы минимизируем loss между предсказанием и истиной. Без учителя истины нет — нет пар, только входы. Целью становится найти структуру, кластеры или уменьшить размерность, и loss формулируется хитро: реконструкция, контрастные пары или информационная мера. Supervised применять легче (данные есть), unsupervised — для исследовательских задач и когда маркировка дорога.

Что такое data leakage и почему это плохо?

Data leakage — когда информация из test/val просочилась в train. Причины: нормализация на всей выборке, выбор признаков на всей выборке, временные ряды где test раньше train, дублирующиеся примеры. Результат: метрика на test нереалистично хороша, потом в боевых условиях модель падает. На экзамене надо знать примеры и правила: scale параметры только из train, feature selection на train, test не смотрим при подборе гиперпараметров.

Чем отличаются недообучение и переобучение?

Недообучение (underfitting): модель слишком простая, большой bias. Loss на train высокий и не снижается, loss на train ≈ loss на val. Лечение: усложнить модель. Переобучение (overfitting): модель слишком сложная, большая variance. Loss на train упал низко, но loss на val выше и растёт. Лечение: регуляризация, больше данных, рано остановиться.

Что такое bias-variance tradeoff?

При фиксированном объёме данных, по мере усложнения модели, ошибка bias монотонно падает (модель может выразить больше), а ошибка variance растёт (чувствительность к шуму выборки). Итоговая ошибка = bias² + variance + шум. Оптимум где-то в середине. На практике: train loss монотонно падает, val loss сначала падает, потом растёт. Точка минимума val loss — это баланс bias и variance.

Параметры и гиперпараметры — в чём разница?

Параметры — это числа внутри модели, которые обучаются из данных (веса $w$, bias $b$). Гиперпараметры — это настройки алгоритма (learning rate, batch size, архитектура, λ регуляризации). Параметры ищем градиентным спуском, гиперпараметры подбираем вручную или через grid/random search на val.

Почему accuracy врёт на дисбалансированных классах?

Пример: 99% данных класс 0, 1% класс 1. Модель выучилась говорить всегда класс 0. Accuracy = 99% ← выглядит отлично! Но Recall для класса 1 = 0%, F1 = 0. Accuracy не учитывает, что нас интересует класс 1. Решение: смотреть на Precision, Recall, F1, ROC-AUC вместо Accuracy при дисбалансе.

Что такое эпоха, батч, итерация и как они связаны?

Выборка N примеров, batch size B. Одна эпоха = N/B итераций (один full pass по выборке). Каждая итерация: берём батч из B примеров, делаем forward, backward, обновляем параметры. Пример: 10000 примеров, batch 100 → одна эпоха = 100 итераций. Батчирование — для параллелизма на GPU и стабильности градиента.

Как выбрать скорость обучения η?

Слишком большое η — расходимся (прыгаем через минимум). Слишком малое — очень медленно. Начни с 0.001 или 0.01 (для нейросетей), посмотри на loss — если падает гладко, хорошо. Если шумит или растёт — уменьши. На практике используют адаптивные оптимизаторы (Adam, RMSprop), которые подбирают η автоматически.

Зачем нужна регуляризация и какие есть виды?

Регуляризация борется с переобучением. Виды: (1) L2 — штраф за большие веса, стягивает к нулю; (2) L1 — штраф за абсолютное значение, обнуляет веса, sparse; (3) Dropout — во время обучения выключаем ~50% нейронов случайно; (4) Early stopping — останавливаем как только val loss начал расти. На практике часто комбинируют: L2 + Dropout + Early stopping.

Почему мы делим данные на train/val/test, если можно обучить на всём?

Потому что на train-данных ты можешь изначально переобучиться, и ты это не заметишь. Val нужен для выбора гиперпараметров и ранней остановки — это объективная мера, как модель работает на новых данных. Test — это финальная проверка, и мы смотрим на test только один раз, чтобы не переобучиться на выбор гиперпараметров даже случайно. Если смотреть на test много раз, то он становится как val, и реальная обобщающая способность неизвестна.

📝 Микро-задачи

Задача 1. Train/val/test split

Выборка 5000 примеров. Нужно разбить на train/val/test в пропорции 60%/20%/20%. Сколько примеров в каждой части?

Решение

Train: $5000 \times 0.6 = 3000$ примеров.

Val: $5000 \times 0.2 = 1000$ примеров.

Test: $5000 \times 0.2 = 1000$ примеров.

Проверка: $3000 + 1000 + 1000 = 5000$ ✓.

Задача 2. Эпохи, батчи, итерации

Обучающая выборка 8000 примеров, batch size 32, планируем 50 эпох. Сколько итераций всего? Сколько итераций в одной эпохе?

Решение

Итерации в одной эпохе: $8000 / 32 = 250$ итераций.

Всего итераций за 50 эпох: $250 \times 50 = 12\,500$ итераций.

Задача 3. Confusion matrix и метрики

На тесте 100 примеров: 50 позитивов, 50 негативов. Модель предсказала: TP = 40, FP = 5, FN = 10, TN = 45. Найди accuracy, precision, recall, F1.

Решение

$\text{Accuracy} = \dfrac{40 + 45}{100} = \dfrac{85}{100} = 0.85 = 85\%$

$\text{Precision} = \dfrac{40}{40 + 5} = \dfrac{40}{45} \approx 0.889 = 88.9\%$

$\text{Recall} = \dfrac{40}{40 + 10} = \dfrac{40}{50} = 0.8 = 80\%$

$\text{F1} = 2 \cdot \dfrac{0.889 \times 0.8}{0.889 + 0.8} = 2 \cdot \dfrac{0.711}{1.689} \approx 0.842 = 84.2\%$

Задача 4. Дисбалансированные классы

900 примеров класса 0, 100 класса 1. Модель выучилась: всегда предсказывает 0. Какая accuracy? Какой recall для класса 1? Что это означает?

Решение

TP = 0, FP = 0, FN = 100, TN = 900.

$\text{Accuracy} = \dfrac{0 + 900}{1000} = 90\%$ ← выглядит хорошо!

$\text{Recall}_{\text{class 1}} = \dfrac{0}{0 + 100} = 0\%$ ← но это плохо!

Смысл: accuracy врёт при дисбалансе. Модель просто игнорирует меньший класс. Надо смотреть на Recall/Precision/F1.

Задача 5. MSE vs MAE

Данные: $y = [1, 2, 3, 4, 100]$ (последний выброс). Предсказания одна: $\hat{y} = [2, 2, 3, 4, 50]$. Считай MSE и MAE.

Решение

Ошибки: $e = [-1, 0, 0, 0, 50]$.

$\text{MSE} = \dfrac{1 + 0 + 0 + 0 + 2500}{5} = \dfrac{2501}{5} = 500.2$ ← квадрат 50 доминирует!

$\text{MAE} = \dfrac{1 + 0 + 0 + 0 + 50}{5} = \dfrac{51}{5} = 10.2$ ← более адекватно.

Вывод: MSE чувствительна к выбросам (квадрат), MAE робастнее.

Задача 6. Learning rate

Миним Loss функции в точке $\theta = 5$. Стартуем $\theta_0 = 0$. Градиент $\nabla L = 2(\theta - 5)$. Начальный градиент $\nabla L(0) = -10$. Какой шаг сделаем с $\eta = 0.1$? С $\eta = 1$?

Решение

$\eta = 0.1$: $\theta_1 = 0 - 0.1 \cdot (-10) = 1$ (мягкий шаг).

$\eta = 1$: $\theta_1 = 0 - 1 \cdot (-10) = 10$ (большой шаг, перепрыгнули минимум!).

Проверка: при $\eta = 1$ мы оказались дальше, чем ошибка — признак слишком большого learning rate.

Скелет устного ответа на билет 0 (вводная)
  1. Общее. ML = поиск параметризованной функции $f_\theta$ по примерам. Три компонента: архитектура, loss, оптимизатор.
  2. Парадигмы. Supervised (есть y, регрессия/классификация), unsupervised (нет y, кластеризация/генерация), reinforcement (награды, агент).
  3. Данные. Train (учим), val (выбор гиперпараметров, ранняя остановка), test (один раз в конце). Утечка данных — беда.
  4. Ошибки. Bias (модель слишком простая), variance (слишком сложная). Underfitting если обе ошибки high на train, overfitting если train low но val high.

  6. Параметры vs гиперпараметры. Параметры (w, b) — обучаются из данных. Гиперпараметры (η, batch, архитектура) — выбираем вручную на val.
  7. Градиентный спуск. $\theta \leftarrow \theta - \eta \nabla L$. Идея: шаги в направлении наискорейшего спуска. η выбирают не слишком большим (расходимся) и не слишком малым (медленно).

  9. Классификация метрики. Accuracy (все классы равны), Precision (FP дорогой), Recall (FN дорогой), F1 (баланс), ROC-AUC (не зависит от порога). При дисбалансе — не Accuracy.

  11. Регуляризация. L2 (штраф за квадрат весов, smooth), L1 (штраф за |веса|, sparse), Dropout (выключаем нейроны), Early stopping (прекращаем когда val растёт).
