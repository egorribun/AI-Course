1. Интуиция и мотивация

Классификация изображений (предсказание одного класса для всей картинки) недостаточна для взаимодействия искусственного интеллекта с физическим миром (автопилоты, медицинская диагностика, робототехника). Компьютерное зрение требует пространственной локализации и сегментации.

Иерархия («Лестница») задач Computer Vision:

  1. Классификация (Classification): «Что на картинке?» $\to$ метка класса (например, «кошка»).
  2. Локализация (Classification + Localization): «Где единственный объект?» $\to$ класс + 1 Bounding Box $(x, y, w, h)$.
  3. Детекция объектов (Object Detection): «Где ВСЕ объекты и какие они?» $\to N$ Bounding Boxes с классами и уверенностью ($N$ заранее неизвестно).
  4. Семантическая сегментация (Semantic Segmentation): «К какому классу относится каждый пиксель?» $\to$ плотная маска классов без разделения отдельных экземпляров (все кошки слиты в одну маску).
  5. Инстанс-сегментация (Instance Segmentation): «Где границы каждого индивидуального объекта?» $\to$ раздельные маски для каждого экземпляра (Кошка #1, Кошка #2).
  6. Паноптическая сегментация (Panoptic Segmentation): Объединение семантической сегментации фоновых текстур («Stuff»: дорога, небо, трава) и инстанс-сегментации счетных объектов («Things»: пешеходы, машины).
  7. Оценка позы и ключевые точки (Pose Estimation / Keypoints): Локализация анатомических сочленений человека (17 точек COCO) или черт лица.
  8. Многообъектный трекинг (Multi-Object Tracking, MOT): Сохранение сквозной идентификации объектов (ID) во времени на видеопотоке.

3. Математический аппарат

3.1 Метрика пересечения IoU (Intersection over Union / Jaccard Index)

Для двух ограничивающих рамок (Bounding Boxes) или пиксельных масок $A$ и $B$:

$$\text{IoU}(A, B) = \frac{\text{Area}(A \cap B)}{\text{Area}(A \cup B)} = \frac{\text{Area}(A \cap B)}{\text{Area}(A) + \text{Area}(B) - \text{Area}(A \cap B)}$$
  • $\text{IoU} \in [0, 1]$. Порог $\text{IoU} \ge 0.5$ (или $\text{IoU} \ge 0.75$) определяет True Positive (TP) детекцию.
  • Generalized IoU (GIoU): $\text{GIoU} = \text{IoU} - \frac{|C \setminus (A \cup B)|}{|C|}$, где $C$ — минимальный выпуклый объемлющий прямоугольник. Имеет ненулевой градиент даже при $A \cap B = \emptyset$.

3.2 Алгоритм Non-Maximum Suppression (NMS)

Устраняет избыточные перекрывающиеся рамки вокруг одного объекта:

  1. Отфильтровать рамки с $\text{Confidence} < \tau_{\text{conf}}$. Отсортировать оставшиеся по убыванию $\text{Confidence}$.
  2. Выбрать рамку $B_{\text{max}}$ с наивысшим баллом, добавить ее в финальный список $\mathcal{D}$.
  3. Вычислить $\text{IoU}(B_{\text{max}}, B_i)$ для всех остальных рамок. Если $\text{IoU} > \tau_{\text{nms}}$ (например, $\tau_{\text{nms}} = 0.5$), удалить $B_i$.
  4. Повторять шаги 2–3, пока список кандидатов не опустеет.

3.3 Метрика mAP (Mean Average Precision)

Для каждого класса $c \in \{1, \dots, C\}$ строится кривая Precision-Recall (PR-Curve) путем ранжирования детекций по убыванию уверенности:

$$\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}}, \qquad \text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}}$$
$$\text{AP}_c = \int_0^1 p_{\text{interp}}(r) \, dr = \sum_{k=1}^N \Big(r_k - r_{k-1}\Big) \cdot \max_{\tilde{r} \ge r_k} p(\tilde{r})$$
$$\text{mAP} = \frac{1}{C} \sum_{c=1}^C \text{AP}_c, \qquad \text{mAP}@[0.5:0.95] = \frac{1}{10} \sum_{\text{IoU}=0.50}^{0.95} \text{mAP}_{\text{IoU}}$$

3.4 Одностадийная детекция и Focal Loss (Lin et al., RetinaNet)

В одностадийных детекторах (Dense Detectors) число ячеек фона достигает $10^5$, подавляя градиенты редких объектов. Focal Loss динамически масштабирует стандартную кросс-энтропию:

$$\text{FL}(p_t) = -\alpha_t (1 - p_t)^\gamma \log(p_t)$$

где $p_t$ — предсказанная вероятность правильного класса, $\gamma \ge 0$ — фокусирующий параметр ($\gamma=2$). Для легких примеров (фон, $p_t \approx 0.99$) множитель $(1-p_t)^2 \approx 0.0001$ подавляет лосс в 10\,000 раз, фокусируя оптимизатор на сложных объектах.

3.5 Функции потерь сегментации: Dice Loss и BCE

$$\mathcal{L}_{\text{Dice}} = 1 - \frac{2 \sum_{i=1}^N p_i g_i + \epsilon}{\sum_{i=1}^N p_i + \sum_{i=1}^N g_i + \epsilon}$$

где $p_i \in [0, 1]$ — предсказанная вероятность пикселя, $g_i \in \{0, 1\}$ — истинная маска, $\epsilon = 10^{-5}$ — сглаживание.

3.6 Реализации на PyTorch

1. Функция вычисления матричного IoU:

import torch
import torch.nn as nn
import torch.nn.functional as F

def box_iou(boxes1, boxes2):
    # boxes format: [N, 4] -> (x1, y1, x2, y2)
    area1 = (boxes1[:, 2] - boxes1[:, 0]) * (boxes1[:, 3] - boxes1[:, 1])
    area2 = (boxes2[:, 2] - boxes2[:, 0]) * (boxes2[:, 3] - boxes2[:, 1])

    lt = torch.max(boxes1[:, None, :2], boxes2[:, :2]) # [N, M, 2]
    rb = torch.min(boxes1[:, None, 2:], boxes2[:, 2:]) # [N, M, 2]
    wh = (rb - lt).clamp(min=0)                         # [N, M, 2]
    inter = wh[:, :, 0] * wh[:, :, 1]                   # [N, M]

    union = area1[:, None] + area2 - inter
    return inter / union

2. Алгоритм Non-Maximum Suppression (NMS):

def non_max_suppression(boxes, scores, iou_threshold=0.5):
    # boxes: [N, 4], scores: [N]
    order = scores.argsort(descending=True)
    keep = []
    while order.numel() > 0:
        i = order[0].item()
        keep.append(i)
        if order.numel() == 1:
            break
        ious = box_iou(boxes[i].unsqueeze(0), boxes[order[1:]]).squeeze(0)
        remaining_indices = torch.where(ious <= iou_threshold)[0]
        order = order[remaining_indices + 1]
    return torch.tensor(keep, dtype=torch.long)

3. Функция потерь Focal Loss:

class FocalLoss(nn.Module):
    def __init__(self, alpha=0.25, gamma=2.0):
        super().__init__()
        self.alpha = alpha
        self.gamma = gamma

    def forward(self, pred_logits, targets):
        # pred_logits: [N, C], targets: [N]
        ce_loss = F.cross_entropy(pred_logits, targets, reduction='none')
        p = torch.exp(-ce_loss)
        focal_loss = self.alpha * ((1.0 - p) ** self.gamma) * ce_loss
        return focal_loss.mean()

4. Функция потерь Dice Loss для сегментации:

class DiceLoss(nn.Module):
    def __init__(self, eps=1e-5):
        super().__init__()
        self.eps = eps

    def forward(self, pred, target):
        # pred, target: (B, 1, H, W)
        pred = torch.sigmoid(pred).view(-1)
        target = target.view(-1)
        intersection = (pred * target).sum()
        dice = (2.0 * intersection + self.eps) / (pred.sum() + target.sum() + self.eps)
        return 1.0 - dice

4. Пошаговый числовой пример

Рассчитаем пошагово IoU, NMS фильтрацию и Average Precision (AP) на тестовой выборке.

🔢 Дано:
  • Истинный бокс объекта (Ground Truth): $GT = [20, 30, 120, 130]$ ($x_1, y_1, x_2, y_2$)
  • Предсказания детектора:
    • Бокс A: $[30, 35, 110, 125]$, $\text{Confidence} = 0.90$
    • Бокс B: $[25, 30, 115, 130]$, $\text{Confidence} = 0.75$
    • Бокс C: $[200, 200, 250, 250]$, $\text{Confidence} = 0.85$ (ложное срабатывание, фон)

Шаг 1. Расчет IoU между боксами A и GT

Площадь $GT$: $(120 - 20) \times (130 - 30) = 100 \times 100 = 10\,000$.

Площадь A: $(110 - 30) \times (125 - 35) = 80 \times 90 = 7\,200$.

Пересечение: $x_1^{\cap} = \max(20, 30) = 30$, $y_1^{\cap} = \max(30, 35) = 35$, $x_2^{\cap} = \min(120, 110) = 110$, $y_2^{\cap} = \min(130, 125) = 125$.

Площадь пересечения: $(110 - 30) \times (125 - 35) = 80 \times 90 = 7\,200$.

$$\text{IoU}(A, GT) = \frac{7\,200}{10\,000 + 7\,200 - 7\,200} = \frac{7\,200}{10\,000} = 0.72$$

Шаг 2. NMS подавление между A и B

Бокс A имеет наивысший $\text{conf}=0.90$, берем его в итоговый список. Вычисляем $\text{IoU}(A, B) \approx 0.85 > 0.5 \implies$ бокс B подавляется.

Шаг 3. Расчет Precision и Recall

Имеем: 1 истинный объект ($GT$). Бокс A: $\text{IoU}=0.72 \ge 0.5 \implies \text{True Positive (TP)}$.

Бокс C: $\text{IoU}(C, GT) = 0 \implies \text{False Positive (FP)}$.

$$\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}} = \frac{1}{1 + 1} = 0.50, \qquad \text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}} = \frac{1}{1 + 0} = 1.00$$

Faster R-CNN Двухстадийный детекционный фреймворк (RPN + RoIAlign). Максимальная точность локализации, надежное обнаружение малых объектов. Низкая скорость ($15\dots 25$ FPS), тяжелая архитектура. Медицинская визуализация, спутниковый мониторинг.

6. 🎯 Препод спросит

Что такое IoU и почему это хорошая метрика?

IoU = (Intersection) / (Union) — отношение площади пересечения двух областей к их объединению. Значение варьируется от 0 (не пересекаются) до 1 (полное совпадение). Преимущества: 1) Инвариантность к масштабу (одинаково штрафует ошибку как для объектов $10\times 10$, так и $1000\times 1000$); 2) Строгая математическая интерпретируемость; 3) Служит стандартизированным порогом (IoU $\ge 0.5 \implies$ True Positive) для вычисления Precision и Recall.

Объясни NMS алгоритм и почему он нужен.

NMS (Non-Maximum Suppression): сортировать боксы по confidence, брать лучший, удалять всех, у кого IoU с ним больше порога (0.5–0.6), повторять. Нужен, потому что детектор часто выдаёт много боксов около одного объекта — все с высокой confidence. NMS оставляет один лучший, остальные — помеха. Интуиция: ящики — это гипотезы, перекрывающиеся гипотезы про один объект конкурируют, берём лучшую.

Как вычисляется mAP? Что мера AP?

AP (Average Precision) — площадь под precision-recall кривой. На оси X — Recall (доля найденных объектов), на оси Y — Precision (доля правильных предсказаний). Меняя порог confidence, получают разные (P, R). Интегрируя кривую, получают AP (одно число). mAP = среднее AP по всем классам (и иногда по порогам IoU). Стандарт COCO: mAP@[0.5:0.95] усредняет IoU пороги от 0.5 до 0.95 с шагом 0.05.

Почему Faster R-CNN двухстадийная, а YOLO одностадийная? Плюсы и минусы.

Двухстадийная (Faster R-CNN): (1) Предложить регионы (RPN), (2) Классифицировать. Плюс: более точна (используются регионы). Минус: медленнее. Одностадийная (YOLO): Сразу предсказать классы и боксы. Плюс: быстрая (real-time). Минус: хуже с малыми объектами, близкими объектами. На практике: Faster R-CNN — точность, YOLO — скорость.

Что такое Focal Loss и когда её использовать?

Focal Loss = $-\alpha(1-p_t)^\gamma \log(p_t)$. Лечит дисбаланс классов (фон vs объекты): умножает каждый пример на вес $(1-p_t)^\gamma$, где $p_t$ — вероятность истинного класса. Уверенные примеры (высокая $p_t$) получают низкий вес, неуверенные (низкая $p_t$) — высокий. Используется в одностадийных детекторах (RetinaNet) и семантической сегментации, где огромный класс фона давит на обучение.

DETR: как это детектирует без anchor'ов и NMS?

DETR выглядит как трансформер для NLP, но адаптирован для детекции. Картинка → CNN extractor → feature map → flatten → Transformer encoder/decoder. На выходе N "queries" (обучаемых векторов, N = max объектов). Каждый query предсказывает (x, y, w, h, class). Loss используется венгерский алгоритм для сопоставления N предсказанных боксов с истинными (padding нулями до N). Нет NMS, потому что loss уже выбирает лучшие соответствия.

Сегментация: семантическая vs instance vs panoptic?

Семантическая: класс каждому пикселю. Два человека = "человек" пиксели, неразличимы. Instance: маска для каждого объекта. Два человека = две отдельные маски. Panoptic: объединение: "stuff" классы (семантические, например небо) + "thing" классы (instance'ы, например люди). По сложности: семантическая < instance (используется Mask R-CNN) < panoptic.

U-Net: почему skip-connections помогают?

При downsampling в энкодере теряется информация о тонкой структуре (края, детали). Skip-connections вводят эту информацию обратно в декодер путём конкатенации. Пример: декодер на уровне 4×4 не знает, где ровно границы объектов (информация в 32×32 feature map энкодера). Конкатенируем → декодер восстанавливает границы точнее. Отсюда название U-shape: информация идёт вниз по левому краю, потом вверх по правому, но не проходит мимо центра.

Dice loss vs Cross-entropy в сегментации. Когда что использовать?

Cross-entropy: $L = -\sum_i g_i \log p_i$, одинаково штрафует за ошибку независимо от её размера. Dice loss: $L = 1 - \frac{2TP}{2TP+FP+FN}$, относит ошибку к площади. При сильном дисбалансе (опухоль 1% картинки) CE дает малые градиенты на миноритарном классе. Dice solution: она инвариантна к дисбалансу. На практике комбинируют: $L = L_{\text{CE}} + L_{\text{Dice}}$.

Ключевые точки: прямая регрессия vs heatmap. Почему heatmap работает лучше?

Прямая регрессия: выход = вектор координат $(x_1, y_1, ..., x_k, y_k)$. Просто, но сложно: предсказать K точек одним вектором, градиенты размазаны. Heatmap: для каждой точки выход = карта вероятности (гауссиан вокруг истинной точки). Работает лучше, потому что: (1) каждая точка — отдельная локальная задача, (2) соседние пиксели дают информацию, (3) неопределённость кодируется в размер гауссиана. Практика: ~75% accuracy (регрессия) vs ~95% (heatmap) на COCO.

SORT vs DeepSORT: в чём разница?

SORT: детектор → Kalman filter (предсказание) → венгерский алгоритм (сопоставление по IoU). Быстро, просто. Проблема: если объект исчезает/переклекивается, может получить новый ID. DeepSORT добавляет: appearance embeddings (хранить и сравнивать внешность объектов). Матрица стоимости сопоставления = $\alpha \cdot \text{IoU\_dist} + (1-\alpha) \cdot \text{cosine\_dist}$. Результат: сохраняет ID при окклюзии. Цена: медленнее (нужна re-ID сеть).

Что такое "anchor" в детекции и почему anchor-free лучше?

Anchor: предопределённые шаблонные боксы (разных размеров и aspect ratio) на каждой позиции feature map. Детектор регрессирует смещения (deltas) к этим anchor'ам. Плюс: регрессировать deltas проще. Минус: нужно выбирать какие anchor'ы, много гиперпараметров, некоторые объекты плохо совпадают с anchor'ами. Anchor-free (FCOS, CenterNet): предсказать координаты прямо (расстояния до границ или центр+размер), без шаблонов. Плюс: проще, нет гиперпараметров. На практике обычно сопоставимо, иногда anchor-free чуть лучше.

7. 📝 Микро-задачи с решениями

Задача 1. Расчёт IoU между двумя боксами

Истинный бокс: $(20, 30, 120, 130)$ (corner format). Предсказанный: $(30, 35, 110, 125)$. Найти IoU.

Решение

Пересечение: $x1 = \max(20, 30) = 30$, $y1 = \max(30, 35) = 35$, $x2 = \min(120, 110) = 110$, $y2 = \min(130, 125) = 125$.

Размеры: $w = 110 - 30 = 80$, $h = 125 - 35 = 90$.

$I = 80 \times 90 = 7200$.

Площади боксов: $A_1 = (120-20) \times (130-30) = 100 \times 100 = 10000$. $A_2 = (110-30) \times (125-35) = 80 \times 90 = 7200$.

$U = 10000 + 7200 - 7200 = 10000$.

$$\text{IoU} = \frac{7200}{10000} = 0.72$$

Задача 2. Прогон NMS вручную

5 боксов: A (conf=0.95, coords), B (conf=0.80), C (conf=0.75), D (conf=0.60), E (conf=0.50). IoU(A, B)=0.7, IoU(A, C)=0.1, IoU(A, D)=0.8, IoU(A, E)=0.05. Порог NMS = 0.5. Какие боксы остаются?

Решение

Шаг 1: Сортировать: A (0.95) > B (0.80) > C (0.75) > D (0.60) > E (0.50).

Шаг 2: Взять A, добавить в keep. Вычислить IoU с остальными:

  • IoU(A, B) = 0.7 > 0.5 → удалить B
  • IoU(A, C) = 0.1 < 0.5 → оставить C
  • IoU(A, D) = 0.8 > 0.5 → удалить D
  • IoU(A, E) = 0.05 < 0.5 → оставить E

Шаг 3: Остались C, E. Возьми C (next conf), добавь в keep. Вычисли IoU(C, E). Если <0.5, добавь E.

(Не дана IoU(C, E), предполагаем <0.5.)

Результат NMS: keep = [A, C, E]. Боксы B и D отфильтрованы.

Задача 3. Расчёт Precision, Recall, AP

На тестовом наборе 10 истинных объектов. Детектор выдал 6 предсказаний. Из них 4 TP (IoU > 0.5), 2 FP (IoU ≤ 0.5). Сколько FN? Найти Precision, Recall.

Решение

TP = 4, FP = 2.

FN = истинные - TP = 10 - 4 = 6 (пропущенные объекты).

$$\text{Precision} = \frac{TP}{TP + FP} = \frac{4}{4 + 2} = \frac{4}{6} = 0.667$$

$$\text{Recall} = \frac{TP}{TP + FN} = \frac{4}{4 + 6} = \frac{4}{10} = 0.4$$

Модель нашла 40% объектов, но из найденных 67% правильны. AP = площадь под P-R кривой; на этой одной точке не определена, нужна кривая при разных пороговых confidence.

Задача 4. Dice coefficient

Маска сегментации. Истина: 100 пиксел класса, предсказано: 80 пиксел. Из них 60 пиксел совпадают (TP). Найти Dice.

Решение

TP = 60, FP = 80 - 60 = 20, FN = 100 - 60 = 40.

$$\text{Dice} = \frac{2 \cdot TP}{2 \cdot TP + FP + FN} = \frac{2 \cdot 60}{2 \cdot 60 + 20 + 40} = \frac{120}{180} = 0.667$$

Или через IoU: $\text{IoU} = \frac{60}{100 + 80 - 60} = \frac{60}{120} = 0.5$.

$\text{Dice} = \frac{2 \cdot 0.5}{1 + 0.5} = \frac{1}{1.5} = 0.667$ ✓

Задача 5. U-Net: роль skip-connections

Энкодер: Input (256×256) → 128×128 → 64×64. Декодер: 64×64 → Upsample → 128×128 → ... → 256×256. Какую информацию теряем при upsampling с 64×64 → 256×256 без skip connections?

Решение

При downsampling: теряется информация о тонкой пространственной структуре (края, детали), которые были в 128×128 и 256×256 feature maps энкодера. При прямом upsampling (без skip) декодер пытается восстановить эти детали из одного 64×64 слоя — невозможно.

Skip-connections: конкатенируем 128×128 feature map энкодера с 128×128 upsampled feature map декодера → декодер получает информацию о структуре → восстанавливает детали точнее.

Результат: с skip-connections точность сегментации выше, особенно на границах объектов.

Задача 6. Heatmap vs регрессия координат

Задача: предсказать 5 ключевых точек лица на картинке 256×256. Вариант A: вектор (x₁, y₁, ..., x₅, y₅) — 10 чисел. Вариант B: 5 heatmap по 64×64 каждая. Какой требует больше памяти? Какой точнее?

Решение

Память (на батч B):

Вариант A: $B \times 10$ float32 = $B \times 40$ байт.

Вариант B: $B \times 5 \times 64 \times 64$ float32 = $B \times 5 \times 4096 \times 4$ байт = $B \times 81\,920$ байт ($\approx B \times 80$ КБ).

Heatmap требует в $2\,048$ раз больше памяти ($81\,920 / 40 = 2\,048$). Поэтому используют компромисс: меньше разрешение heatmap (например 32×32).

Точность: Heatmap ~95% accuracy на COCO (стандарт). Прямая регрессия ~75%. Heatmap выигрывает благодаря локальной структуре и информации от соседних пиксел.

8. ⚡ Скелет ответа по билету

Скелет устного ответа по билету 13: Задачи Computer Vision (Детекция, Сегментация, Трекинг)
  1. Лестница задач CV: Классификация $\to$ Локализация $\to$ Детекция ($N$ боксов) $\to$ Семантическая сегментация (класс на пиксель) $\to$ Инстанс-сегментация (маска каждого объекта) $\to$ Паноптическая (Stuff + Things) $\to$ Ключевые точки $\to$ Трекинг.
  2. Метрики детекции: IoU = $\frac{\text{Intersection}}{\text{Union}}$. NMS: удаление перекрывающихся дубликатов. AP: площадь под PR-кривой. mAP@[0.5:0.95]: стандарт COCO.
  3. Двухстадийные детекторы (Faster R-CNN): Backbone $\to$ RPN (генерация proposals с anchor boxes) $\to$ RoIAlign (билинейная интерполяция без округлений) $\to$ классификационная и регрессионная головы. Высокая точность, умеренная скорость.
  4. Одностадийные детекторы (YOLO / RetinaNet): Прямое предсказание классов и координат по сетке. RetinaNet решает проблему дисбаланса фона через Focal Loss $\text{FL}(p_t) = -\alpha(1-p_t)^\gamma \log(p_t)$. Real-time скорость.
  5. Anchor-Free и Transformers (DETR): FCOS/CenterNet (предсказание центров/смещений). DETR (Transformer Encoder-Decoder, Bipartite Matching с венгерским алгоритмом, без NMS).
  6. Сегментация (U-Net, Mask R-CNN): U-Net: энкодер-декодер со Skip-Connections для точного восстановления границ. Mask R-CNN: добавление FCN ветки масок к Faster R-CNN. Функции потерь: BCE + Dice Loss.
  7. Ключевые точки и трекинг: Heatmap-регрессия (гауссианы вероятностей) точнее прямой векторной регрессии. MOT: парадигма Tracking-by-Detection (SORT с фильтром Калмана, DeepSORT с re-ID эмбеддингами, ByteTrack с низкопороговыми детекциями).
